# StickMon 存档兼容与迁移规则

## 当前基线

- 当前存档版本：v4（`Game::SAVE_VERSION`），以源码为准。
- 最低支持版本：v1。
- v1/v2 的核心游戏状态为固定 1560 字节；旧主界面视图记录为 44 字节。
- v3 追加普通头目保底字段，状态尺寸变为 1572 字节；v4 复用尾部对齐字节
  存放 `debugMotionFlags`（AMOLED debug「运动」开关：倾斜控制/行走边界/
  对话点），尺寸仍为 1572。
- 新写入走 `SaveCodec`（SVC2）：当前 schema 2；schema 1（v3 载荷）可解码，
  新增字段按默认值补齐，加载成功后自动重写为当前 schema。
- v1 原始记录和开发期产生的 v1 + 主界面视图 v2 过渡记录均可按迁移链升到
  当前版本。

## 版本规则

1. 任何持久化字段的新增、删除、改类型、改顺序或改数组长度，都必须提升 `SAVE_VERSION`。
2. 每次升级只实现相邻版本迁移，例如 v3 -> v4；较老版本按迁移链逐级升级。
   SaveCodec 载荷按 schema 编号兼容解码，新字段只在 schema 达到引入它的
   版本时读取。
3. 旧格式必须使用冻结的旧结构或固定字节载荷读取，不能用当前结构体解释旧数据。
4. 迁移先校验旧版本魔数、版本和校验和，迁移成功后才写入新版本。
5. 主界面位置等非关键视图数据损坏时，只重置视图，不能清除队伍、背包、金币和探索进度。
6. 遇到高于当前固件的版本、读取失败或校验损坏时进入写保护，禁止自动保存覆盖原数据；用户明确重置存档后才解除。
7. 删除旧迁移器前，必须先提升 `MIN_SUPPORTED_SAVE_VERSION`，并明确对应版本已不再受支持。

## 开发流程

1. 冻结上一版本的结构尺寸、字段偏移和测试样本。
2. 提升 `SAVE_VERSION`（和 SaveCodec schema），新增上一版本到当前版本的迁移函数。
3. 为旧版本二进制样本增加 host 测试，验证核心进度、可选视图和自动重写。
4. 验证损坏视图不丢核心进度，未知未来版本不会被覆盖。
5. 运行全量 host 测试及 release/debug 固件构建。

主要实现位于 `src/core/SaveManager.cpp` 与 `src/core/SaveCodec.cpp`，版本
常量位于 `src/game/GameState.h`。
