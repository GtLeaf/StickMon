# StickMon 开发计划 v0.1

记录日期：2026-06-27

## 1. 项目边界

StickMon 是运行在 M5Stack StickS3 上的便携电子宠物游戏。目标是先做出一个稳定、可携带、可保存、可单机游玩的养成闭环，再逐步加入 ESP-NOW 对战、交换与通讯进化。

本计划以 `StickS3_电子宠物机_玩法与技术设计文档_v0.1.md` 的后半段 v0.2 补丁集为准。旧文档中与本计划冲突的内容，按本计划处理。

## 2. 硬约束

- 不实现 IR 通信。
- 不初始化 IR TX/RX，不引入 IR 链路层，不做 IR 唤醒、IR 交换、IR 通讯进化。
- 设备互联只使用 ESP-NOW。
- 通讯进化由 ESP-NOW 的交换/进化会话触发，仪式感通过屏幕动画、双方确认、SAS 4 位校验实现。
- 首发版本优先离线可玩；Wi-Fi 联网只作为后续天气/活动扩展，不阻塞核心玩法。
- UI 固定按 StickS3 竖屏 135x240 设计。
- 两键输入优先，Mic/IMU 是增强输入，不可成为必需操作。
- 所有玩家可见 UI 文案使用中文，并集中管理，避免散落硬编码。

## 3. 技术路线

### 3.1 工程基线

- 构建系统：PlatformIO。
- 框架：Arduino。
- 目标板：ESP32-S3 / M5Stack StickS3。
- 核心库：M5Unified、M5GFX。
- 分区：8 MB Flash，保留 NVS、factory、OTA0、OTA1、SPIFFS/LittleFS。
- 存档：ESP32 Preferences/NVS，双缓冲 + CRC。
- 工程配置参考 PokeBug：
  - `platform = espressif32 @ 6.6.0`
  - `board = esp32-s3-devkitc-1`
  - `framework = arduino`
  - `board_build.arduino.memory_type = qio_opi`
  - `board_build.partitions = default_8MB.csv`
  - `build_flags` 必须包含 `BOARD_HAS_PSRAM`、`ARDUINO_USB_CDC_ON_BOOT=1`、`ARDUINO_USB_MODE=1`
  - `lib_deps` 使用 `m5stack/M5Unified@^0.2.3`、`m5stack/M5GFX@^0.2.3`

### 3.2 PSRAM 使用策略

StickMon 默认启用 PSRAM，并把它当作渲染和动画性能优化层：

- 双 framebuffer / 大 sprite 缓冲优先放 PSRAM。
- 精灵渲染优先使用 `PokemonSprites` 压缩资源；资源缺失时保留色块/几何 sprite 作为降级路径。
- 宝可梦原型图像资源通过 `tools/generate_pokemon_sprites.py` 从 Pokemon Essentials 源图重新生成 RGB565 RLE C++ 常量，避免运行时解 PNG。
- 属性特效、状态效果、房间背景缓存优先使用 PSRAM。
- 高频小对象、场景状态机、存档镜像仍放 SRAM / NVS，避免 PSRAM 访问延迟影响逻辑。
- 若 PSRAM 初始化失败，降级到单 framebuffer + 简化特效，但核心玩法仍可运行。

## Milestone 4：图鉴、属性与单机战斗

目标：可以进行稳定的 PvE 战斗。

交付：
- 首发 32 只开发期 StickMon 数据
- 属性表压缩 LUT
- 普攻 + 特殊技触发系统
- 伤害公式
- 状态异常基础框架
- PvE 战斗场景
- 濒死轮换流程
- 战斗奖励：经验、金币、亲密度变化
- 常驻全队经验共享：队首获得完整战斗经验，未濒死且 HP 大于 0 的后备额外获得 50%；后备濒死或 HP 为 0 时不获得经验
- 努力值不参与经验平分：出战精灵和未濒死且 HP 大于 0 的后备精灵，各自获得被击败物种的完整努力值产出
- 全局等级上限为 Lv.100；经验成长按 Pokemon Essentials 六条 `GrowthRate` 曲线实时计算，运行时经验使用 32 位累计值，等级由曲线反推并刷新 HP 上限。Lv.100 累计经验分别为 Erratic 600,000、Fast 800,000、Medium 1,000,000、Parabolic 1,059,860、Slow 1,250,000、Fluctuating 1,640,000
- 招式维持“1 个基础招式 + 最多 2 个特殊招式”的轻量结构：第一特殊技通常在 Lv.7 学习，鲤鱼王在 Lv.15 学会撞击；存在属性高级技的精灵在 Lv.35 学习第二特殊技。高级技表按属性集中配置，新增日光束、飞翔、污泥炸弹
- 熟练度属于特殊招式而不是精灵：两个特殊招式槽分别保存 `0～100` 熟练度；造成有效伤害后仅实际使用的特殊招式 `+1`，新学会或替换进入槽位的招式从 `0` 开始。基础招式默认满熟练度且不展示。特殊招式基础触发率采用平滑 S 曲线，熟练度 `0/25/50/60/75/90/100` 分别对应 `15%/19%/28%/31%/36%/39%/40%`；亲密度最多额外 `+10%`，HP 低于 30% 时额外 `+5%`，每个特殊招式最终仍封顶 `40%`。熟练度不额外改变伤害和命中率
- 野生精灵创建、升级学习、捕获校验和读档清理统一读取同一份学习表；宿主机回归测试覆盖 Lv.1～100 的经验反查和代表性技能里程碑

验收：
- 战斗能完整开始、结算、返回主界面。
- HP、伤害、命中、特殊技触发可通过日志复核。
- 全队濒死会退出战斗并进入静养代价。

## Milestone 5：探索与捕捉

目标：打通“走路/探索 -> 遭遇 -> 战斗 -> 捕捉 -> 入队/入库”的核心玩法。

- 玩家确认探索地点后先返回房间，精灵从活动区走向门口并穿门离开，再以黑幕渐隐/渐显切入探索场景。
- 正常结束探索时，队首沿最终出口方向继续走出画面，后备按现有间距跟出；最后一只精灵完全离屏后才显示“探索结束”弹窗。玩家确认后渐隐探索场景，房间从黑幕渐显后精灵由门外走回活动区；门口通道仅在进出门动画期间开放。
- 濒死退出探索不播放走路进门，黑幕切回房间后直接在床上进入休息状态。

交付：
- 26x26 格位可滚动探索场景，精灵和地块均约为原尺寸的 0.8 倍
- 小型 Roguelite 随机拓扑：地图数量随场景等级从 `3～4` 层递增到 `7～9` 层，整局固定使用玩家选择的场景画像与难度；后续每层使用独立 seed 生成同场景的新地图，显示 1～2 个实体出口及其道路。当前阶段由运行时随机选择其中一条行走路线，但保留其他出口和备用路线
- A 键单步移动并播放对应方向的一轮走路帧，停止后保持最后方向的 `walk0`；B 键弹出结束探索确认框
- 步数阈值遭遇
- 天气接口占位，本地 fallback
- 捕捉指令与球种选择
- IMU 投球力度
- 捕获概率
- 图鉴首次捕获奖励
- 仓库满时拒绝捕获并提示

验收：
- 30-120 步随机遭遇逻辑可运行。
- 捕捉成功会写入队伍或仓库。
- 捕捉失败会消耗球并继续战斗。

水域身份不能被当前碰撞规则抹掉：`terrainTag 5/6/7` 分别保留为深水、静水和普通水，并在 `floatBlocked` 中只解除水面图块自身的 `0x0f` 阻挡；水上建筑或岸线结构仍保持阻挡。`terrainTag 8/9` 的瀑布及瀑布顶虽然标记为水域，但普通漂浮能力不开放，后续如需攀瀑应增加独立能力。调试图绿色表示从入口陆行可达，蓝色表示需漂浮能力到达的水面，深蓝表示已识别但尚未与入口连通的水面，青色表示普通漂浮不可通过的水域，红色表示陆行不可达，红色短边表示该方向的陆行阻挡；白框为入口、黄框为出口。

`.smonmap` 当前仍是自由探索、碰撞和按精灵能力选择通行掩码的参考格式；运行时随机图暂时沿生成器同时产出的两条路线移动，尚未启用逐格自由碰撞。固定预制路线已退出运行时。

运行时随机地图算法 v8 位于 `src/game/ExploreMapGenerator.cpp`。每进入一层都根据远征 seed、层号和场景号派生独立 map seed，在 RAM 中生成 `16x12x3` tile ID、入口、真实分叉点、两个不同边缘的出口和两条路线；下一层入口固定为本层所选出口的相反方向。除霜晶冰窟的专用房间模板外，拓扑、地表装饰和场景特征继续使用独立 XorShift32 流。两条路线只共享入口到分叉点的主干，从分叉点立即朝各自出口方向展开，禁止回退、重复经过主干或在分叉区外形成相邻的并排道路；两格宽道路的最外圈占用只能是入口与出口的两格门口，转向段必须退回地图内部，禁止沿地图边缘延伸。

区域编号 `1`（溪桥坡地）启用专用溪流阶段：生成器最多进行 16 次由原 seed 派生的确定性拓扑尝试，枚举宽 3～5 格、只在同一个两行桥区与道路相交的竖向溪流。溪流可保持直线，或在桥面及上下各 2 格以外做一次渐进变宽/变窄；单侧岸线每次最多移动 1 格，禁止等宽横移。变宽使用 `1088/1090 + 1104/1106` 岸角，向下收窄使用纵向翻转派生 tile `4400～4403`。桥面使用 Layer 2 的 `1627/1643`，水中石块只放在 `1097` 水面且避开路线、桥面、其他石块及转角周围 1 格。

同一区域可在溪流一侧生成一条水平同高悬崖：崖顶 `1188` 位于 Layer 0，崖面 `1185` 位于 Layer 1，两格楼梯 `1161/1162` 必须与上下道路连续。楼梯左右至少各有 1 格同高崖肩，路线与崖带只能在楼梯四格相交，悬崖不得覆盖溪流或桥梁。没有完整合法候选时跳过悬崖，不以错层或遮挡方式强行放置。

区域编号 `5`（古木瀑谷）启用专用瀑谷阶段。生成器根据入口方向选择四个已验证拓扑之一，每张均有一个真实分叉点和两个出口；先放 8 帧 Sea 上下游，再放 4 帧瀑布顶/身/底、带瀑布缺口的同高墙与贯穿整段的两格楼梯，最后补顶边森林、水中石块和岩石。瀑底 Sea 圆角 `84/80` 含透明像素，必须放在 Layer 1，并在同格 Layer 0 预铺 `385`；圆角黑点表示透明像素落到了空图层，禁止通过修改原始 Sea 像素掩盖。顶边森林片段只能从 `y=0` 向下延伸，可占据左上/右上角，但不得作为内部、底边或脱离顶部的侧边模块。

v8 保留原有地点画像，并将区域 `3` 霜晶冰窟维持为四种已确认房间模板：曲折岩丘入口、纵向冰池厅、纯雪地双厅和横向冰带环廊。左右入口使用两种横向模板并按需水平镜像，上下入口使用两种纵向模板并按需垂直镜像；入口和两个出口始终保持双格开口。只有曲折入口使用透明 3x3 岩丘，两种纵向模板使用连续冰面，纯雪地双厅两者都不用，禁止强制每图同时出现小岛和冰面。纵向冰池路线从入口侧沿同一列滑出冰面后再进入分叉厅；横向冰带路线先从普通地面绕到冰带端点，沿同一行滑到对岸后再进入分叉，分叉点、Boss、物品和保底战斗均不得位于冰面。积雪岩壁按 `1296/1297/1298, 1304/1305/1306, 1312/1313/1314` 语义自动补齐凹角并计入阻挡；带背景岩丘因底色不匹配而禁用。霜晶顶部出口使用完整三格 `1299/1300/1301`，映射为运行时 `4741/4742/4743`，仅在不会覆盖另一条路线时写入；底部出口使用 `1333`，映射为 `4747`。`1322` 破冰洞、`1341` 洞、`1326/1327` 圆形水面角块和 `1344～1363` 连续岩边只登记为事件/模板资源，不作为普通随机装饰。运行时先按普通 Layer 1 绘制全部岩壁，再在拾取物、Boss、队首和跟随精灵之后重绘南向外墙 `4517～4519` 与南向凹角 `4522/4523`；只由 tile 自身非透明像素形成遮挡，保证屏幕下方岩壁覆盖其后的道路与经过的精灵，北向和侧向墙不进入前景重绘。场景编号严格按菜单顺序连续定义为 `0～5`，并由编译期断言保证场景枚举、地图生成器和捕获来源使用同一编号。

霜晶光滑冰面统一包含中心 tile `4504` 和轮廓 tile `4524～4531`。队首踏入后锁定进入方向，以每格 `180ms` 线性恒速滑到冰面结束；滑行中 A/B 输入、菜单、随机战斗、保底战斗、物品和 Boss 均不打断移动，但每格仍累计步数、喷雾消耗、战斗冷却和队伍步数恢复。若同方向的下一路线格不存在，则按障碍物处理并停在当前冰格；正常模板必须让路线直穿冰面并在冰外保留停靠格。`ExploreIceSlide.h` 保存方向锁定、连续滑行、直线验证和事件迁移规则，Python 镜像生成器执行同样的路线验证。

#### 探索地图图层组合规则

程序生成或重绘 RPG Maker XP 风格地图时，必须保留三层 tile 语义，按 `Layer 0 -> Layer 1 -> Layer 2` 顺序使用透明像素合成；不能将多层模板误当作独立单块。普通地面和森林主体放 Layer 0，栅栏等结构放 Layer 1，跨越结构前景的树冠、屋檐等透明装饰放 Layer 2。`Tilesets.rxdata` 中的 passage/priority 继续决定碰撞和角色遮挡，不能用视觉层替代碰撞层。

Map039 Route 4 的森林栅栏是首个标准模板：

- `800～803`、`808～811`、`816～819` 是 `Graphics/Tilesets/Outside.png` 中的森林主体，禁止当作完整独立树木散放。唯一允许的裁切形式是 `top_edge_forest_clusters`：它表示森林从画面上方继续进入地图，顶行必须严格位于 `y=0`，不得放在地图内部、底部或作为脱离顶部的左右侧边模块；位于 `y=0` 的左上/右上角仍属于合法顶部延伸。
- `1662`、`1665`、`1681`、`1682` 是同一 tileset 中的栅栏角、竖边和横边，放在 Layer 1，并承担不可通行碰撞。
- `804/805` 是透明树冠尖端，必须在栅栏同一行交替放到 Layer 2；其非透明像素覆盖栅栏，透明区域保留栅栏可见，因此形成树木与栅栏自然重叠。
- `804/805` 保持 `priority=1` 和可通行；森林主体与栅栏保持不可通行。不得通过复制 RGB 像素改变这些语义。
- Map039 底部森林的完整纵向序列为：Layer 2 的 `804/805` 树冠；Layer 0 的 `810/811` 接缝行；一组或多组 `800～803 -> 808～811` 树顶/树身对；最后才是 `816～819` 根部。根部上一行必须是 `808～811` 树身，禁止把 `800～803` 树顶直接拼到 `816～819` 根部。
- 生成器必须调用 `tools/map_generation_rules.py` 的 `stamp_forest_fence`，并验证每段森林主体都有对应的 Layer 2 树冠。该模板从树冠行到根部至少需要 7 行，Layer 0 主体高度必须为不小于 6 的偶数。左右、底部或地图内部需要树木时，应使用完整独立树模板或该多层森林模板，不能只放 `800～819`。
- 古木瀑谷参考 Map069 Route 8 的 autotile 槽位顺序。上下游水面统一使用 8 帧 `Sea` 槽位 `48～95`：中心水面 `48`、左岸 `64`、上岸 `68`、右岸 `72`、右上岸角 `80`、左上岸角 `84`；瀑底通过 `top_open_spans` 保留落水口，双瀑之间使用 `68` 连续封岸，禁止使用静态 `1096/1097/1098`。`84/80` 带透明外角，必须放在 Layer 1，并在同索引 Layer 0 预铺 `385` 草地；黑点是透明像素露出空图层的故障信号，回归测试必须逐格验证该双层关系。
- 瀑布顶 `240～287`、瀑身 `288～335`、瀑底 `336～383` 均沿用 Map069，其中 Sea 为 8 帧、瀑布三段为 4 帧。Python 预览按 8 帧循环并令瀑布使用 `frame % 4`；`terrainTag 8/9` 不向普通漂浮开放。详细拼接规则见 `doc/essentials_map_analysis/Essentials地图生成规则.md`。
- `Graphics/Tilesets/Outside.png` 的 `3941～3983` 中存在一套完整 `3x6` 白色灯塔，按 `tools/map_generation_rules.py` 的 `LIGHTHOUSE_TILE_ROWS` 原顺序放在 Layer 1；上部图块的 `priority=2～5` 用于角色遮挡，底部两行不可通行，禁止拆成单块装饰或改变行顺序。
- 灯塔必须依附连续海域、岛屿、礁石平台或防波堤，不能放在普通草地旁的小池塘中。Map039 左岸可作为标准海岸模板：`144` 深海主体、`168` 深海边缘、`72` 近岸过渡，再连接陆地；生成器统一调用 `stamp_left_coast`。小型封闭水池使用 Map028 的 `1088～1106` 岩岸静水模块，并保留原始 `StillWater(6)`。`392～410` 实际是空地而非水面，禁止用于任何水域，也禁止通过覆盖 passage/terrainTag 将其伪装成水面。
- Map028 Natural Park 使用 `391` 作为更高的前景草，放在 Layer 1，保持 `priority=1`、`terrainTag=10`；普通可遇敌草 `390` 仍放在 Layer 0。高草可以覆盖普通草地，但不得覆盖道路、出口、水面、灯塔或森林结构。
- `859` 是 Map039 Route 4 与 Map044 Route 6 实际使用的圆灌木，保持 Layer 1 和不可通行语义。运行时只能把它组成依附草区、森林或结构边界的短直线/边界段，禁止在开放地面随机散放，也禁止插入 `390` 草区内部。

道路默认采用“两格宽多出口网络”规则：一张地图允许 1～2 个实体出口，每个出口都必须拥有从入口可达的连续世界坐标路线。多条路线优先共享入口侧主干，在真实分叉点后立即分离，不能回退主干，也不能生成不通向入口、出口或明确事件点的装饰性死路。所有实体出口的路线一起传给道路生成器，栅格化为恰好两格宽的道路并合并重复主干；精灵沿两格之间的中心线移动，不受单格中心约束。每一格道路都必须落在至少一条有效路线的两格宽包络内，路线覆盖率必须为 100%；转角、T 形和十字路口只扩展到连接两格走廊所需的最小范围，分支离开分叉区后不得重叠或正交相邻。地图最外圈除各入口/出口的两格门口外必须保持无道路，所有边缘转向段至少向内退一格。只有显式标记为广场、休息区或事件区的区域才允许额外扩宽。中心线使用半格坐标，生成器统一调用 `tools/map_generation_rules.py` 的 `build_two_tile_road`，按相邻道路格自动选择 `537～558` 的边缘、转角与内部图块，并拒绝斜线段或落在单格中心的道路中心线。

探索开始时按场景分别决定地图数量：草丛小路 `3～4`、溪桥坡地 `4～5`、高草公园 `4～6`、霜晶冰窟 `5～7`、雾隐林径 `6～8`、古木瀑谷 `7～9`。两档范围各占 50%；三档范围按 `25% / 50% / 25%` 选择，使中间值最常出现。整局固定使用玩家选择的场景画像和难度，不再在层间随机跳到其他场景。每一层继续使用独立 seed 生成不同地图、入口、1～2 个出口和路线；两个出口都通往同一场景的下一张随机地图，当前阶段仍随机选择其中一条行走路线并保留备用路线。最终层抵达任一有效出口后结束本轮。这样场景菜单表达稳定的难度选择，深入加成也不会被跨场景等级跳变抵消。菜单显示推荐等级但不硬锁，允许玩家自行挑战高等级地点。

每张地图必须至少包含一次有效事件：约 65% 的地图在当前选定路线上保证放置 1 个物品，其余地图不放物品，而是在战斗冷却结束后的内部路线点保底触发 1 场战斗；如果抵达保底点前已经随机遇敌，则该场战斗直接满足保底。上一场战斗的剩余冷却覆盖全部内部路线点或路线过短时，战斗型地图自动回退为物品地图，禁止为满足保底而跳过冷却。随机遭遇按地图独立限制为最多 2 场；每次遭遇触发后设置 5 个完整移动步的冷却，冷却跨地图延续，但新地图会重置该图的遭遇计数。冷却步即使触发拾取或抵达出口也会正常消耗，第 6 个完整移动步才重新允许遭遇判定。运行时生成失败会依次尝试四个确定性 seed，全部失败后使用已覆盖六场景与四入口方向的安全 seed `1`；仍失败时立即结束远征，不继续使用半生成地图。

战斗经验参考 GBA 的“物种经验基值 × 对手等级 / 7”结构；物种经验基值使用官方 BaseExp 数据。相较旧的固定“对手等级 ×3”，高等级战斗奖励会随物种强度增长，使 Lv.60 之后仍能沿 Lv.100 成长曲线推进。
队伍经验采用常驻学习装置规则：队首获得上述完整经验，未濒死且 HP 大于 0 的后备额外获得 50%；没有健康后备时只结算队首经验。后备升级、进化和学会招式与出战精灵一样通过战斗日志播报。
努力值不按参与精灵数量拆分：出战者与每只健康后备都获得野怪的完整物种产出，并分别受单项 252、总计 510 上限约束；濒死后备不获得。

当前阶段实现 Roguelite 的随机地图拓扑、运行时 tile 地图和区域头目。地图节点继续沿用现有普通探索、随机拾取、遭遇、战斗和捕捉逻辑；除区域头目外，不新增奖励结算、休息点、遗物、扩展事件、精英、独立远征存档、断电恢复、难度层级、每日种子或挑战模式。

探索精灵按 0.8 倍绘制，与 26x26 地块占位同步。队伍存在第二只精灵时，后备在入口旁侧错开一个完整地块，等队首积累两步路径后再并入，之后始终跟随队首两步之前的真实路径位置；队首先移动 `120ms` 后后备再起步，没有位移时不空播动画或增加等待。两只精灵按世界 Y 坐标排序绘制，镜头与事件触发仍只跟随队首。每次按 A 向下一格目标移动，并使用平滑插值；镜头跟随队首世界坐标，触及地图边界后停止滚动。移动方向映射为正面、左、背面、右四组 walking 资源，缺少右向原图时水平翻转左向帧；一次移动按 `0 -> 1 -> ... -> 末帧 -> 0` 播放完整一轮，不再叠加漂浮位移。移动结束后不再回退到 `ICON_0`，而是保持最后移动方向对应的 `walk0`；切换地图时则使用该地图入口方向的 `walk0`。路线上的精灵球保持落地位置，不再上下悬浮，视觉锚点比路径地块中心下移 `6px` 以对齐精灵落脚点。探索右上角场景名使用与主界面一致的深色半透明 HUD（`alpha=150`）；战斗双方 HP 面板使用白色半透明底（`alpha=200`），保留深色边框与文字。B 键在行走阶段打开结束探索确认框并暂停当前移动，默认选中“继续”，A 确认并从原进度恢复，B 切换选项。战斗结束后从当前路线位置继续，并受单图遭遇上限和战后步数冷却约束。

捕捉菜单支持精灵球、高级球、沉重球、时间球。高级球固定提高捕获率；沉重球根据目标基础能力总和加成；时间球随当前战斗回合数提高加成。捕捉动画为非阻塞时间轴，按钮和场景主循环保持运行。

### 6.2.1 战斗招式与特性边界（2026-08-13）

战斗核心不再将所有固定威力招式默认视为完整支持。生成器按机制白名单输出可学习招式，无法表达完整规则的招式保留在 PokeAPI 源快照中，但不会进入运行时学习池；完整明细由 `tools/pokemon_data/oras_unsupported_moves.csv` 自动生成。

当前已落地的特殊招式规则包括：两回合蓄力、破坏光线类硬直、自爆类使用者濒死、点到为止保留 1 HP、逆鳞类锁招与混乱、滚动/连斩连续增伤、食梦与打鼾的使用条件、条件威力、辅助力量、火箭头锤防御提升、珍藏使用条件、突袭失败条件、逐步击破、龙尾结束野外战斗、冷冻干燥对水属性特效和必定暴击。

物种特性使用统一静态映射，并参与战斗结算；已支持茂盛、猛火、激流、鳞粉、蜕皮、复眼、静电、结实、飘浮、适应力、储水、蓄电、引火、大力士、孢子、单纯、坚硬岩石、精神力、技术高手、威吓、厚脂肪和同步。状态页与战斗读取同一映射，不再为未配置物种默认显示“同步”。悠游自如保留数据映射，待天气系统落地后生效。

以下招式依赖当前尚不存在的 PP 或携带物系统，已从运行时升级招式表删除：

- PP：怨恨、王牌。
- 携带物：小偷、渴望、查封、投掷、虫咬、杂技。
- 同时涉及道具或回复限制：回复封锁。
- `自然之恩`也列入生成器排除清单；当前 64 只精灵的 ORAS 升级表没有该招式。

恢复上述招式的前置条件是：为每只精灵保存各招式当前 PP、实现 PP 消耗/补充/耗尽流程，以及为精灵增加独立携带物槽和战斗中的道具转移、消耗与禁用规则。恢复时必须先补存档版本迁移，不能只取消生成器过滤。

### 6.3 主界面世界模型

主界面是精灵房间，不是静态看板。首版实现一个小型宠物活动区：

- 精灵在不规则活动区内移动、停留、睡觉、靠近食物；移动使用碰撞体校验和轻量路径重规划，不能穿出活动区。
- 精灵基础作息为 22:00 开始准备上床、06:00 起床。速度上升性格更活跃，作息为 22:30～05:30；速度下降性格更嗜睡，作息为 21:30～06:30；其他性格保持基础作息。濒死休息和异常状态睡眠不受日常作息限制，睡眠时段的饱食度衰减使用较慢档位。
- v0.1 可互动项只做两类：摸一摸、向碗里加食物。玩家不能直接投喂，精灵根据饱腹、昼夜和当前行为自行决定何时进食。
- 主界面 AI 分为需求、动作、导航三层。需求包含进食、休息、漫游、发呆，并带意图惯性；动作包含转身、移动、唤醒、进食、休息，避免行为频繁跳变。
- 运动速度、停留时间和漫游范围由精灵速度种族值、性格及少量物种配置共同决定；菜单往返时保留位置、朝向、目标和可恢复动作。
- 精灵优先使用压缩图像资源；美术资源缺失时统一降级为色块/几何 sprite 表示。
- 渲染对象带 `z` 或 `layer`，基础层级为 `background -> floor/props -> shadow -> monster -> state_effect -> interaction_prop -> HUD -> toast/modal`。
- `z` 轴同时用于后续扩展状态表现，例如睡觉在床后、濒死倒地、开心跳跃、饥饿靠近食物、特殊技蓄光。

### 6.4 时间与 OOBE
