# AMOLED V1 触控校准

日期：2026-10-19。适用于 SH8601 / FT3168 的物理 V1，代码仅修改
`firmware/amoled_1_8_v1/main/TouchInput.cpp` 和 V1 主循环中的触摸日志。
V2 的 CST820 参数、FT 兼容参数及板级实现均保持不变。

## 原因和参数

物理 V1 的九点实测曾在运行 V2 目标固件时完成，正确拟合只保留在 V2 的
FT 兼容分支中。V1 工程仍使用旧的向内收缩参数，造成边缘触点偏向中心。
本次把属于物理 V1 的结果应用回独立 V1 驱动：

```text
x = clamp(round(rawX * 1.1179618 - 20.711235), 0, 367)
y = clamp(round(rawY * 1.0494687 - 21.692282), 0, 447)
```

保留原有方向、368×448 原生坐标、移动/抬起事件与中断唤醒行为。
启动日志明确输出 `Touch calibration profile: V1 FT3168 (0x38)`；
V1 DOWN 日志同时记录 raw 和 display 坐标，便于采集独立验证数据。

## 自动化验证

```sh
python3 tools/test_amoled_v1_touch.py
python3 tools/test_amoled_v2_touch.py
python3 tools/test_amoled_touch_test.py
```

V1 测试独立编译真实 TouchInput，覆盖九点回放、边界裁限、全轴单调性、
移动/释放、120ms 超时、长按中断屏蔽、唤醒失败与控制器缺失。
V2 测试仅执行回归，不改写其文件；另核对 V2 TouchInput.cpp/.h 与 main.cpp
修改前后的哈希，确认板级代码未变。V1 lite debug 与 lite release 构建通过。

刷入前已读取并备份当前 V1 自身的 NVS；应用更新不擦除 NVS 或资源分区。
重新插拔后确认物理 V1 的 MAC 为 `1c:db:d4:7a:16:dc`，重新备份其 NVS，
仅更新应用分区并通过写入校验。启动确认 FT3168 地址为 `0x38`，使用
`V1 FT3168 (0x38)` 校准配置，存档正常加载，初始画面与触摸初始化成功。
