# 本地产物管理规范

从 2026-10-24 起，需要保留的临时文件、验收截图、bug 排查日志和冻结源码统一放在
仓库根目录 `.stick-local/`。整个目录由 `.gitignore` 忽略，不提交到 Git。

| 内容 | 位置（相对于仓库根目录） |
| --- | --- |
| 同一任务的验收截图、导出帧、日志、性能数据和源码快照 | `.stick-local/artifacts/<任务名>-<YYYYMMDD>/` |
| 独立串口采集和排查日志 | `.stick-local/logs/` |
| 临时地图、房间、家具等预览 | `.stick-local/previews/` |
| 设备分区、NVS 和配置备份 | `.stick-local/backups/` |
| 临时脚本、试验文件和手工保留的中间文件 | `.stick-local/scratch/` |
| 确认稳定前暂存的待清理资源 | `.stick-local/unused-resources/` |
| 手动导出的刷机二进制包 | `.stick-local/firmware/<目标>/` |
| 整理清单和校验记录 | `.stick-local/maintenance/` |

同一验收任务的证据尽量放在一起，例如 `before/`、`after/`、`frozen/`、`screenshots/`
和 `logs/`。文档保留结论、复现步骤及相对于仓库根目录的证据位置；大批截图、原始日志、
完整源码副本和临时排查脚本放本地目录。此类文件只在本机保留，需要长期备份时另行备份。

在仓库根目录执行命令时，先建立输出目录，再指定输出或重定向日志，例如：

```bash
mkdir -p .stick-local/artifacts/touch-check-20261024
python3 tools/test_amoled_room_preview.py > .stick-local/artifacts/touch-check-20261024/tests.log 2>&1
python3 tools/generate_frost_crystal_cave_preview.py --output-dir .stick-local/previews/frost-crystal-cave
```

新增或修改工具时，临时输出默认指向 `.stick-local/` 下对应子目录，且保留显式指定输出路径
的能力。在其他工作目录调用时，默认路径也应根据脚本位置解析到仓库根目录。
浏览器下载的临时预览、手动截图和排查资料同样归入此目录。

以下内容继续保留现有约定：

- 正式源码、维护中的工具、构建或运行时使用的资源，以及经审查的 `tools/fixtures/`
  回归基线，继续纳入版本管理。判断用途后再迁移，不能仅凭名称含 `generated` 或
  `preview` 就移动。修改基线需独立审查，不能用新基线掩盖行为变化。
- 当前使用的构建系统目录 `.pio/`、`build/`、`firmware/**/build*/` 保持原位；
  已停用的历史缓存可归档。手动导出和 V2 发布包统一放 `.stick-local/firmware/`。
- 测试自动清理的 `TemporaryDirectory`、工具缓存和虚拟环境沿用原规则；需要人工
  保留的临时数据或排查环境应放 `.stick-local/scratch/`。
- 正式文档中的少量说明图、资源设计图册和必须版本管理的样例，按原用途维护。

提交前检查暂存区，确保没有混入临时产物。禁止对 `.stick-local/` 使用强制添加。
不要在 `tools/out/`、根 `out/`/`output/`、`src/`、`doc/` 等目录新建临时验收目录。
