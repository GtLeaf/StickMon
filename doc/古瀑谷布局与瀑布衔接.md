# 古瀑谷布局与瀑布衔接

2026-10-25，地图算法版本 **24**，区域编号 5。森林与高桥已写入正式探索流程和地图包，未刷机。

## 当前地图与连通

共 **13 种物理地图样式**：森林 A～F 六种、原山洞 A～D 四种、高桥洞 A～C 三种。
高桥 A 的上下层共用一张图，因此内部寻路使用 14 个节点，不计作第 14 种样式。
每次古瀑谷探索从森林 A 南侧进入；森林节点通过以下双向连接互通：

- A 北 ↔ B 南，A 东 ↔ D 西。
- B 北 ↔ E 南，B 东 ↔ C 西。
- C 南 ↔ D 北，C 北 ↔ F 南，E 东 ↔ F 西。
- E 的洞口通向原山洞 A；F 的洞口通向高桥 A 下层。
- 原山洞 A/B/C/D 保留，内部连接为 A↔B、A↔D、B↔C、B↔D、C↔D，C 有外部出口。
- 高桥固定行程为 **A 下层 → B 楼梯登高 → A 上层过桥 → C 楼梯下行 → 外部出口**。
  A 下层不可直接进入桥面，也没有桥下穿行路线。

沿用原探索的自动分路机制；每次生成提供通向其他可达出口的路线，排除本次进入的洞口。
边界道路退出到屏外，洞口原地转场。对应森林边界的方向、道路位置严格配对。
森林 A 南侧、原山洞 C 和高桥 C 的外部出口可结束探索。
普通换图消耗一个探索段；高桥 A/B/C 的内部换图不额外计段，保证完整走完高桥。
原有 7～9 段上限仍生效：森林或原山洞到达上限后结束；高桥则在 C 出口结束。
Boss 与最终奖励判断跟随所走路线是否终结，不再只依据段数，避免提前截断高桥。

## 随机范围与可维护来源

- 森林保留已确认的 38/91 两组配方，每组含完整 A～F 六图及树木、道路、装饰和洞口。
- 高桥保留四种结构，每种选四组已验证装饰配方，共 **16 套完整 A/B/C 组合**。
  结构覆盖河道位置／宽度、桥高、瀑布高度、B/C 楼梯与出口位置；细节包含岩石簇、
  坑穴、原地面拼块和小支路。不是运行时无限重排，也不宣称所有种子都有唯一地形。
- 整次探索使用同一探险种子选择配方，重复进入森林或 A 桥厅不会重新抽样。
- 维护源为 `tools/valley_forest_design.json`、`tools/valley_bridge_layouts.py` 和
  原 `tools/ancient_valley_layouts.json`。运行 `python3 tools/valley_region.py` 生成
  `src/game/ExploreValleyData.h`；`generateValleyRegion` 和 Python 的

  正式固件从上述 16 套中选择，双方随机范围应明确区分。

峡谷画面**左岸 Caves:590／右岸 588**，Layer 1 岸壁下保留 Layer 0 洞穴地面 610；
不交换、不镜像，不改铺水面或整片 513。独立细水岸为 Outside:1136/1138。
瀑布必须有完整上游供水与封闭承接潭，泡沫下一行保持开放水面，两侧不得出现横向干岸。
水面保留八帧、瀑布保留四帧；预览的 96 映射至已有 5013（Sea without shore 原变体 0）。
详见 [地图生成规则](essentials_map_analysis/Essentials地图生成规则.md)。

| 本层入口 | 布局 | 结构 |

## 洞口、路线与遮挡

- 北洞口：原 `524` 上块与 `532` 下块，插入连续北洞壁。
- 南洞口：Layer 1 原 `507/508/509`，Layer 2 中心原 `516`，两侧接连续 `505`。
- 西／东洞口：分别用原 `517/515`，相邻洞壁保持 `514/512`。
- 每个洞口内侧保留两格干燥接近区。两条分支路线均使用格心坐标，楼梯只允许纵向经过。
  路线、角色脚部采样不得穿过瀑布、水潭、崖面或装饰岩石。
- 洞口是传送入口；走到路线终点后原地进入原有退出过场，伙伴也不向屏外穿墙。
  横屏 ExploreScene 和 AMOLED ExplorePresenter 都调用共享 `interiorPortalExit`。
- 两个北洞口块共用下块下缘深度，崖面、南洞口前沿和小岩石按地面深度恢复遮挡。
  横屏与 AMOLED 均启用该区域的角色深度排序，角色图像地面锚点与格心路线一致。
- 新地面进入 ROCK 生态语义；只有完整开放水面进入游泳栖息语义，岸边和瀑布仍阻挡。
  水中物种沿用现有鱼类限定。
