# StickMon 羁绊系统设计与实现说明

> 文档状态：已落地功能说明  
> 更新日期：2026-07-29  
> 适用版本：首发存档版本（无旧存档迁移）

---

## 一、系统定位

羁绊表示玩家与某只精灵之间的长期关系，主要影响：

1. 通讯录中显示的关系阶段；
2. 邀请通讯录精灵加入队伍时的答应概率；
3. 挚友主动来访、送礼或邀请探险；
4. 一起探险后的关系成长；
5. 探险濒死造成的关系损失。

羁绊与以下数值相互独立：

- **心情**：短期情绪，受饥饿、洗澡等照护行为影响；
- **亲昵度（affection）**：已有养成字段，当前不参与通讯录邀约；
- **战斗结交值**：战斗中投掷食物、异常状态等影响结交判定，结交成功后才创建通讯录记录。

---

## 二、数值范围与阶段

羁绊使用有符号整数，范围为 `-100～100`。所有增减均在边界处截断，不会溢出。

| 数值范围 | 通讯录显示 | 含义 |
|---|---|---|
| `-100～-51` | 抗拒 | 对玩家明显抵触 |
| `-50～-1` | 疏远 | 关系冷淡，不愿同行 |
| `0～24` | 初识 | 已认识，但信任有限 |
| `25～49` | 熟悉 | 愿意尝试同行 |
| `50～74` | 信赖 | 邀约成功率较高 |
| `75～100` | 挚友 | 接受邀约，并可能主动来访 |

新结交的精灵初始羁绊为 `10`，对应“初识”。

通讯录只展示阶段名称，不展示“羁绊：”前缀或具体数值。

## 三、羁绊变化

### 3.1 一起探险

一次探险结束时，根据本次步数统一结算：

| 本次步数 | 羁绊增加 |
|---|---:|
| `0` | `0` |
| `1～14` | `+1` |
| `15～39` | `+2` |
| `40～79` | `+3` |
| `80+` | `+4` |

规则：

- 队伍中的正式精灵均可获得；
- 接受挚友邀请后同行的临时访客也可获得；
- 已濒死或 HP 为 0 的精灵不获得本次羁绊；
- 普通 ESP-NOW 临时访客不参与本地羁绊结算；
- 单次探险只结算一次，防止重复打开结束页面反复领取。

### 3.2 探险濒死

精灵在探险中濒死时：

- 羁绊 `-10`；
- affection `-5`；
- 心情 `-10`；
- 同时执行现有经验损失和濒死休息逻辑。

羁绊允许降到负值，最低为 `-100`。

### 3.3 挚友来访

挚友以“来家里玩”的事件进入房间时，羁绊 `+2`。

送礼和邀请探险事件本身不直接增加羁绊；邀请探险的收益由实际完成的探险步数结算。

### 3.4 当前不增加羁绊的行为

以下行为目前不会改变羁绊：

- 普通喂食；
- 洗澡；
- 摸一摸；
- 使用药品；
- 单纯放在队伍或房间中；
- 战斗胜利本身。

这些行为仍可改变心情、经验、HP 或其他养成数值。若后续接入羁绊，应设置每日上限，避免挂机照护替代探险。

## 四、通讯录邀约

玩家在通讯录中选择精灵并执行“邀请”后，显示确认对话。邀约概率如下：

| 羁绊阶段 | 答应概率 |
|---|---:|
| 抗拒 | `5%` |
| 疏远 | `15%` |
| 初识 | `35%` |
| 熟悉 | `60%` |
| 信赖 | `85%` |
| 挚友 | `100%` |

刚在战斗后完成结交的精灵，第一次邀请为 `100%`，保证“结交后立即入队”的流程不会再次失败。

### 4.1 邀约失败

- 精灵婉拒邀请；
- 该通讯录条目整体变灰；
- 当天不能再次邀请该精灵；
- 状态页与删除操作仍可使用；
- 每天 `07:00` 进入新的邀约日，解除上一日锁定。

锁定按精灵分别记录，不会因为另一只精灵邀约失败而影响全部通讯录。

### 4.2 邀约成功

- 精灵加入队伍后仍保留在通讯录中；
- 对应名字灰显，并在名字后标记“队伍中”；
- 队伍期间不能重复邀请或删除该联系人；
- 状态页读取队伍中的实时数据，存档及离队时同步回原通讯录记录；
- 队伍上限仍为 2；
- 成功后清除该精灵的邀约失败标记；
- 队伍中的第二只正式精灵会在房间中出现并消耗饥饿度。

## 五、双精灵房间状态

当队伍中有两只正式精灵时：

- 第一只作为主界面主精灵；
- 第二只作为房间伙伴独立移动；
- 两只精灵都消耗饥饿度；
- 右上角面板纵向显示两组 HP 与 HUN；
- 睡眠、移动和门口进出需要保持间距，避免重叠；
- 只有第一只响应主界面的直接喂食、摸一摸等单体操作。

将第二只设为首位后，两只精灵交换队伍顺序，主界面展示和直接互动目标随之变化。

双方的房间互动、触发限制与心情奖励见
《[双精灵房间互动设计与实现说明](双精灵房间互动设计与实现说明.md)》。

## 六、挚友主动来访

### 6.1 触发条件

主动来访需要同时满足：

- 队伍中只有 1 只正式精灵；
- 通讯录中至少有 1 只羁绊 `75+` 的挚友；
- 候选精灵未濒死且 HP 大于 0；
- 当前没有 ESP-NOW 来访；
- 当前不处于探险出发或归来流程；
- 距离该精灵上次来访至少 3 个游戏日。

满足条件后，每个邀约日进行一次确定性判定，触发概率为 `20%`。同一天重复进入房间不会通过反复重载改变结果。

### 6.2 事件分布

来访成功后，从以下事件中选择：

| 事件 | 权重 | 效果 |
|---|---:|---|
| 来家里玩 | `45%` | 进入房间，羁绊 `+2` |
| 送礼 | `35%` | 赠送 1 份普通粮 |
| 邀请探险 | `20%` | 询问是否一起去探险 |

主界面先显示“好像有敲门声，要去看看吗？”。接受后，精灵从门外走入房间。

拒绝敲门不会扣除羁绊，但当天不会再次触发同一轮来访。

## 七、临时同行与归还

主动来访的精灵仍保留在通讯录中。运行时会创建一份临时同行副本，用于房间表现、战斗状态和探险结算。

### 7.1 首位规则

- 临时访客允许被设为首位；
- 设为首位后可作为主界面精灵和探险出战精灵；
- 临时访客不能被“存入”通讯录，也不能删除原通讯录记录；
- 探险结束时，系统先将原本的正式精灵恢复为首位；
- 随后同步访客的 HP、状态、经验和羁绊，再将临时副本移出队伍。

### 7.2 探险归来流程

正常流程：

1. 两只精灵按门口顺序回到房间；
2. 访客对话表示本次探险很开心；
3. 访客告别；
4. 访客走出房间；
5. 临时同行状态同步回原通讯录记录；
6. 队伍恢复为来访前的单精灵状态。

接受邀请后，如果玩家在区域选择页取消，也会走告别和离场流程，不会残留临时队员。

### 7.3 异常恢复

- 访客会话只存在于运行时，不作为长期队伍成员保存；
- 重启加载存档时会清理临时访客副本，通讯录原记录仍保留；
- 离场前若通讯录中删除了其他条目，系统会同步修正访客原记录的位置；
- 若进出门寻路超时，会直接完成访客归还，避免卡死在房间状态。

## 八、存档与实现约束

- 羁绊存储在 `MonsterRuntime::bond`，类型为 `int8_t`；
- 复用首版 `MonsterRuntime` 的既有字节，结构大小保持 64 字节；
- 当前尚未发板，以现有结构作为存档 v1，不提供开发期存档迁移；
- 邀约日锁定复用通讯录精灵的 `petCountToday` 高位；
- 来访会话、事件类型和临时队员身份为运行时状态；
- 所有羁绊增减必须通过饱和计算，保持在 `-100～100`。

核心实现位置：

- `src/game/BondSystem.h`：阶段、增减、邀约概率和邀约日；
- `src/core/GameEngine.cpp`：邀约、来访、临时同行和探险结算；
- `src/scenes/MenuScene.cpp`：通讯录显示、置灰和邀约交互；
- `src/scenes/MainScene.cpp`：敲门、进门、房间停留、归来对话和离场；
- `src/game/CareTicker.h`：双正式队员的饥饿度消耗。

## 九、后续可扩展项

以下方向尚未实现：

- 通讯录筛选与按羁绊排序；
- 来访记录或事件回顾；
- 不同精灵的来访礼物池；
- 邀请探险时指定区域或提出目标；
- 负羁绊对应的修复关系事件；
- 羁绊阶段变化时的专用提示；
- 玩家与精灵之外的“精灵间关系”数值。

新增系统时应继续保持：羁绊代表长期关系，心情代表短期状态，避免多个数值承担同一种反馈。
