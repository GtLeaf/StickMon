# 房间与家具分层

微雪 AMOLED Debug 入口：`Debug → 环境 → 房间`。
床与地毯分别选择「森林」「星月」「云朵」，共 6 件详细原款；重启恢复原样。
当前预览不修改存档，也不改变床、食盆、门口及精灵行为位置。

## 结构

- 空房底图：`origin_asset/room/standar/room_empty.png`（1672×941）。
- 房间配置：`room_layout.json` 中的尺寸、摆放、活动区、床铺、门口与行为锚点。
- 家具纹理：每件独立 `.smonfurn`，只保存颜色和透明度，不带房间底图或位置。
- 房间包：v6 `.smonroom`，包含空底图、几何、默认家具 ID、摆放及房间对应的投影阴影。
- 缓存合成：首次显示、更换家具/房间、昼夜变化时重建 RGB565 缓存。普通帧只复制缓存，不读文件、不解码、不重复叠加。

运行时先叠加地板阴影，再按配置顺序绘制家具及家具接收的阴影。
日夜窗户是两个按时段显示的摆放槽。槽的名字和数量通用，床、地毯只是目前
Debug 菜单提供的两个入口。最多 32 个摆放槽，只加载当前房间选择的家具。

`RoomResource::setFurniture(slot, assetId)` 只换指定槽，其他家具及房间几何不变。
同一款重复选择不触发缓存更新。纹理读取、CRC32 或解码失败时保留旧选择。
`RoomResource::selectRoom(roomId)` 事务替换底图、摆放、默认家具和几何；失败时
保留当前房间。v2/v3/v4/v5 房间读取兼容。

当前换款共享槽的目标大小、碰撞及投影阴影。未来改变家具形状、移动位置或更换
房间布局时，应从房间编辑器重新导出几何、行为锚点和阴影；纹理仍可复用。
精灵与高大家具的前后遮挡、收集/制作玩法、房间选择 UI 及存档持久化不在本次范围。

## 资源生成

```sh
python3 tools/generate_room_layers.py
```

需要 Pillow。默认读取正式布局和家具库，输出
`origin_asset/generated/room/layered/{rooms,furniture}/` 与 `standard.json` 资源清单。
当前包含 1 个房间、6 件原家具纹理、6 件新款纹理，不再生成混搭组合。
原家具纹理 ID 按内容生成；同内容再导出保持稳定。新款使用可读的稳定 ID，
如 `bed_forest_leaf`、`rug_cloud`。

新增房间示例：

```sh
python3 tools/generate_room_layers.py \
  --layout path/to/room_layout.json --id garden \
  --furniture-dir path/to/furniture --no-variants
```

为房间提供自己的空底图、摆放和几何，可引用已有家具源图。生成的所有房间与
家具包会被 AMOLED Debug 自动收集；按 `garden` 加载时采用其默认摆放和行为锚点。
生成器根据各房间 JSON 资源清单清理本次导出淘汰的纹理，保留其他房间仍引用的资产。
生成后需重新构建。Release 和 StickS3 继续使用正式 v4 房间，不带这些 Debug 资源。

## 格式

v6 保留 v4 的 80 字节房间头、RGB565 日间底图和几何编码，夜间补丁字段为 0。
几何之后追加 `<IHH`：夜间底图压缩长度、摆放数、保留字段（0），然后是可选
RGB565 夜间底图的 raw-deflate 数据；无数据表示复用日间底图。

每个摆放记录为小端 `<24s32shhHHHhhHHII`（82 字节）：槽 ID、默认纹理 ID、
图像 x/y、目标宽高、flags、阴影 x/y/宽高、日夜阴影压缩长度。
flags：1=日间显示、2=夜间显示、4=接收其他家具阴影。
紧接本记录保存日间与可选夜间的 raw-deflate 阴影 alpha8；夜间长度 0 表示复用日间。
位置和尺寸采用房间 art 坐标，与玩法 world 坐标由 artScale 对应。

`.smonfurn` 头为 `<IHHHHIII`（24 字节）：magic=0x4e525546、version=1、
宽、高、flags=0、原始长度、压缩长度、原始数据 CRC32。
每像素为 RGB565 小端颜色两字节 + alpha8 一字节，使用 raw-deflate；加载后展开为
RGBA 缓存，合成时临时使用 RGB888，最终量化为屏幕 RGB565。
相较原离线先合成后量化方式，透明边缘存在少量颜色量化差异。
