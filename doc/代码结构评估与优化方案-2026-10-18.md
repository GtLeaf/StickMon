## 判断

整体具备健康的分层基础，应用层的职责与状态管理需要优先整理。适合分阶段重构，每批保持现有功能可运行，并独立验收。

已有的基础值得继续使用：

- `src/game/` 已承载经验、照料、洗澡、战斗数值、房间仲裁和导航等共享能力。
- `PlatformServices` 隔离硬件，Desktop 和 Web 能运行真实游戏代码；本次架构边界检查通过。
- `SaveCodec` 使用显式编码和版本迁移，`SaveManager` 提供双槽快照保护。
- 微雪已有页面模型、独立设置页/房间菜单/孵化页、渲染缓存生命周期和局部重绘验证。
- V2 已复用 V1 的应用和渲染代码，已有 `ui/sources.txt` 作为多目标渲染源清单。

## 执行顺序

### 第 1 批：建立重构保护和统一构建入口

1. 将吃饭唤醒、两只精灵轮流进食、避让、濒死恢复、探索返回、战后保存、升级学招等现有关键行为固定为可执行用例。
2. 对即将拆分的功能，先补等价行为检查，再替换依赖具体源码片段的测试；保留真正有价值的边界静态检查。
3. 扩展已有源清单机制，让应用拆分后的源文件同时被 V1、V2、原生测试和 Web 使用；共享业务源清单也逐步去重，继续明确排除设备专用代码。
4. 增加 PR 检查：共享规则、存档迁移、页面渲染和触摸行为。固件及 Web 构建按改动范围触发，避免每次无差别执行所有昂贵任务。

验收：同一批应用源可被四个运行目标消费；被迁移的用例不再依赖函数所在文件；现有检查保持通过。

### 第 2 批：先拆微雪页面控制，再统一房间状态

第一步从设置、队伍/背包、洗澡、孵化等边界较清楚的页面开始。每页集中自己的输入、临时状态、更新和页面模型生成；渲染模块仅接收模型并绘图。

`AmoledApp` 保留应用启动、时钟、场景路由和模块协调。模块获得明确依赖与少量操作接口，避免让每个模块持有任意修改整个应用的权限。

第二步整理房间：

- `Home::Actor` 作为位置、目标、任务和路由的唯一权威来源。
- 主精灵和伙伴采用相同的任务执行入口；空闲决策、进食、睡眠和资源让路在已有共享服务上继续收拢。
- 动画帧、呼吸、表情、跳跃和镜头仍由表现层负责，通过快照读取任务结果。
- 转身等暂停需要明确规定由谁掌握任务推进权，避免业务和动画各自推进一次。
- Stick 与微雪的布局、几何参数、避让模式继续通过配置表达。

验收：正常运行不再需要在两份主精灵位置之间来回复制；两只精灵同一套生存规则；访客进出、锁屏、照料经验和避让用例全部通过。

### 第 3 批：共享战斗执行和升级后续，收拢保存请求

1. 在现有 `BattleSystem`、`BattleTurnController` 上增加共享行动执行入口，统一检查、蓄力、自伤、伤害与附加效果的规则顺序。
2. 执行结果返回有序的语义事件，例如使用技能、混乱自伤、伤害、免疫、状态变化、濒死；两端自行映射文字、动画和音效。
3. 明确每个行动只提交一次业务变更；动画提交或跳过只推进表现，避免重复扣血或重复结算。保持同一随机种子下的结果与随机调用顺序可比较。
4. 将经验到账之后的升级、进化、学招式事件生成收进共享流程，两端只决定展示方式与返回页面。
5. 为微雪接入共享保存调度接口，区分立即、尽快和延后请求；保留已约定的金币/物品拾取和战斗结算退出保存边界。失败保留待存状态，受保护的新版本存档继续禁止写入。

验收：同一初始状态和随机序列，两端最终 HP、状态、经验、等级和待处理成长事件一致；重放/跳过动画不重复提交；保存失败可重试，探索不恢复逐步同步写盘。

### 第 4 批：收拢设备公共实现，继续整理大型场景

- 将 V1/V2 重复的平台服务和主循环公共部分移到 `firmware/common/`，板级文件保留屏幕、触摸、引脚、初始化和 OTA 能力差异。
- 将剩余 `.inc` 页面逐个改为独立 `.h/.cpp`，使用已有 `UiCommon` 和页面模型，消除依赖包含顺序的辅助函数。
- 将整理好的共享流程逐步接入 Stick 的大场景，避免同时改动两套所有表现代码。
- 可在这一批统一微雪公共应用目录命名，消除“共享应用挂在 V1 目录”带来的理解成本；目录搬迁应独立验收。

验收：公共电量/音频/主循环修复只需修改一处；三个固件构建通过；V1/V2 分别完成显示、触摸、锁屏和唤醒实机检查。

## 实施约束

- 每批只迁移一个明确功能域，保留可工作的检查点，避免整套应用同时改写。
- 优先使用固定容量状态、明确所有权和已有服务；无需为每一项功能引入动态分配、通用事件总线或插件体系。
- 本轮结构整理原则上保持存档格式；若出现持久化字段调整，另行执行 schema 与迁移流程。
- 每批对受影响目标运行检查：共享代码覆盖三固件，微雪公共代码覆盖 V1/V2，Web 使用的公共代码覆盖两个模拟器。固件编译与原生测试不能代替实机验收。
- 性能收益需要用帧时、写盘耗时、内存和设备功耗测量。重构首先解决维护与一致性问题。
