# StickMon 探索模式精灵分布方案

> 基于 `src/scenes/ExploreScene.cpp` 遭遇表重构  
> 目标：将此前未登场的 22 只精灵（排除神兽/幻兽/卡比兽后）按进化等级合理分布至 6 大区域。  
> v1.1 追加：**§七 栖息地轮换机制（大量出现）**——区域菜单预览从静态 top-3 改为动态活跃池，探险遭遇与预览一致。  
> v1.2 追加：**§7.9 稀有精灵结交成功率测算与窗口兑现**——稀有池内权重 ×3 加成 + 结交连败保底；§7.4 示例与 §7.6 存档字段同步修订。
> v1.4 修订：**§7.9.4 结交保底重做**——单槽连败计数改为按物种独立的成功率累积（+3pp/败，上限 5 层），仅对较少及以上稀有度 + 神兽幻兽记录；§7.6 存档字段同步修订。
> v1.3 追加：**§八 特殊精灵与游荡机制**——卡比兽、梦幻、拉帝亚斯、拉帝欧斯通过区域头目、幻影事件和游荡机制登场，不进入普通活跃池；特殊活动地图名称使用明亮青色，拉帝兄妹游荡战与梦幻事件统一为 Lv.70。
> v2.0 修订：① **通讯进化终段隔离**——#094 耿鬼、#076 隆隆岩、#212 巨钳螳螂撤出全部野生遭遇表，只能 ESP-NOW 交换进化；前段（鬼斯通/隆隆石/飞天螳螂）保留野生。② **多区域渗透**——精灵可分布在符合进化等级的多个区域，前段渗透等级上限 ≤ 进化等级−1，最终形态及无条件进化形态无封顶。本文档 §一~§六 的表格均为 v2.0 修订后的最终状态。
> v2.1 追加：**霜晶洞窟 / 古木瀑谷扩编**——霜晶 +2（超音蝠高级个体、奇鲁莉安），古瀑 +6（冰鬼护、大狼犬、鬼斯通、大嘴蝠、水箭龟、妙蛙花），解决两区种类过少问题；§4.1 稀有度归类调整（新增「非常稀有」档），§4.4 区域稀有度占比校验。

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **进化等级对齐** | 精灵投放区域与其进化等级匹配。一段形态出现在低级区域，二段/三段形态随等级提升向高级区域迁移。 |
| **通讯进化终段隔离（v2.0）** | 通讯进化链的终段（耿鬼、隆隆岩、巨钳螳螂）不投放任何野生区域。前段野生可得，终段只能通过 ESP-NOW 交换进化——联机玩法的核心激励。 |
| **多区域渗透（v2.0）** | 精灵不限定单一区域。前段形态向相邻高一级区域渗透时等级上限 ≤ 进化等级−1；最终形态及无条件进化形态（亲密度/进化石/通讯）无封顶。渗透权重 2~5，从该区域头部常见精灵匀出，区域总和守恒 100。 |
| **御三家递减稀有度** | 御三家初始形态权重≈1（极稀有）；二段形态权重≈1（极稀有）；三段形态权重=1（极稀有）。三段不叠加额外衰减，因为本身已处于最高级区域。 |
| **进化形态衰减** | 同一条进化链中，后段形态的遭遇权重低于前段。例如：波波(17) → 比比鸟(6) → 大比鸟(3)。 |
| **伊布家族集中** | 伊布及其 5 种进化形态（水/雷/火/太阳/月亮）集中在 MIST_FOREST_PATH，营造"森林深处遇伊布"的主题感。 |
| **权重守恒** | 每个区域 `EncounterEntry.weight` 之和恒为 **100**，仅做内部再分配。 |
| **稀有度占比上限（v2.1）** | 每个区域内，高稀有度精灵（稀有+非常稀有+极稀有）的权重合计必须**低于**不稀有精灵（常见+普通+较少）的合计，保证任何区域刷怪时"普通的多、稀罕的少"。逐区校验见 §4.4。 |
| **特殊遭遇隔离** | #143 卡比兽、#151 梦幻、#380 拉帝亚斯、#381 拉帝欧斯不进入普通遭遇表和活跃池，通过 §八 的区域头目、幻影事件和游荡机制独立登场。 |

## 七、栖息地轮换机制（大量出现）v1.1

> 机制定位：把区域菜单的预览从"装饰性的 top-3"升级为"本时段真实可遭遇的活跃池"。
> 所见即所得——预览里看到的，就是这趟探险唯一能遇到的。

### 7.1 机制概述

- 每个区域维护一个**当前活跃池**：从该区域遭遇表（§三）中随机抽取 **4 ~ 6 只**精灵。
- 池组成：基础 **4 ~ 5 只普通精灵** + 可选 **0 ~ 2 只稀有精灵**。
- 区域菜单预览展示活跃池**全部**成员（替代现有 `encounterPreviewSpecies()` 的固定 top-3）。
- 探险中**只遭遇池内精灵**，遭遇权重按原表 `weight` 在池内重新归一化。
- 区域头目（`expeditionBossSpeciesId`）走独立路径，**不受活跃池限制**。

### 7.2 刷新（重抽）规则

重抽只由以下两个事件触发，**菜单切换、进出区域、存档读档（SL）均不重抽**：

| 触发 | 范围 | 说明 |
|------|------|------|
| **击败区域头目** | 仅该区域 | 战胜该区域 Boss 后立即重抽该区域活跃池。给玩家一个可控的"刷新手段"，但需付出打 Boss 的成本 |
| **时段轮换** | 全部区域 | 游戏内时间每 **8 小时**轮换一次，一天正好早 / 中 / 晚三个时段，所有区域统一重抽 |

实现约定：

- 时段序号 = `gameMinutesTotal / 480`（游戏内分钟，480 = 8h）。序号变化即触发全区域重抽，基于 `GameEngine` 已有的游戏时钟，无需新增计时器。
- 每个区域维护一个**重抽计数**（击败头目时递增），存入存档，防止重启回滚到上一池。
- 池种子 = `mix(时段序号, 区域ID, 重抽计数)`。池内容由种子**确定性重建**，活跃池本身不进存档（见 §7.6）。

### 7.3 抽取规则

**池划分（不新增表字段，直接复用 §4.1 稀有度矩阵的权重阈值）：**

| 池 | 判定 | 覆盖稀有度 |
|----|------|-----------|
| 普通池 | `weight ≥ 4` | 常见 / 普通 / 较少 |
| 稀有池 | `weight ≤ 3` | 稀有 / 极稀有（含全部御三家、伊布家族） |

**槽位与概率：**

| 槽位 | 数量 | 抽取方式 |
|------|------|---------|
| 基础槽 | 4 ~ 5（均匀随机定 4 或 5） | 从普通池**均匀不放回**抽取 |
| 稀有槽 | 0 / 1 / 2，概率 **40% / 40% / 20%** | 从稀有池**均匀不放回**抽取 |

- **均匀抽取**保证跨轮换各精灵登场机会均等，利于集图鉴；趟内的常见/稀有层次由 §7.4 的权重归一化承担，两者不冲突。
- 兜底：普通池不足 4 只时全取；稀有池为空时稀有槽恒为 0。

**各区域池容量校验（基于 §三 最终表，均满足 4~5 + 0~2）：**

| 区域 | 普通池（weight≥4） | 稀有池（weight≤3） |
|------|------|------|
| 草地小径 | 7 | 3（伊布、妙蛙种子、小火龙） |
| 溪桥坡地 | 8 | 8（尾立、土狼犬、波波、拉鲁拉丝、迷你龙、杰尼龟、火恐龙、卡咪龟） |
| 高草公园 | 9 | 9（长翅鸥、呆火驼、斗笠菇、雷丘、鬼斯、伊布、飞天螳螂、妙蛙草、迷你龙） |
| 霜晶洞窟 | 8 | 4（大比鸟、比比鸟、奇鲁莉安、水箭龟） |
| 迷雾森道 | 6 | 8（水/雷/火/太阳/月亮伊布、大嘴蝠、哈克龙、妙蛙花） |
| 古木瀑谷 | 8 | 7（快龙、大狼犬、鬼斯通、大嘴蝠、喷火龙、水箭龟、妙蛙花） |

### 7.4 遭遇权重动态调整

- 探险中在活跃池内滚点；`rollEncounterEntry()` 本身就是运行时动态求和归一，传入过滤后的池视图即可，**无需改动现有函数结构**。
- 每只精灵保留自己在原表中的 `minLevel ~ maxLevel` 等级范围，不受影响。
- **稀有成员池内权重加成 ×3**（`weight ≤ 3` 的池成员滚点时按 `weight × 3` 计）：兑现"窗口承诺"，数值论证见 §7.9。

**示例（草地小径）：** 抽出基础槽 {绿毛虫 18、尾立 19、铁甲蛹 15、拉鲁拉丝 8} + 稀有槽 {小火龙 1→×3 计 3}，池内权重和 63：

- 绿毛虫单次遭遇率 18/63 ≈ 28.6%（原表 18%），小火龙 3/63 ≈ 4.8%（原表 1%）；
- 一趟探险约 12 次遭遇，小火龙趟内遭遇期望 ≈ 44%（无加成时仅 18%，见 §7.9）。

**稀有度保护论证（为什么不会通胀）：** 稀有精灵进池概率受"槽位概率 × 池内均匀抽"双重限制。以小火龙为例：P(进池) = 40%×1/3 + 20%×2/3 ≈ 26.7%，长期折算单次遭遇率 ≈ 26.7% × 4.8% ≈ **1.3%，仅为原表 1% 的 1.3 倍**。即：长期期望与原表基本持平（如需严格守恒可将加成降为 ×2，长期 ≈ 0.86%），但体验从"均匀稀薄"变为"**间歇集中**"——池子里出现御三家时玩家有明确的时间窗口去刷，这正是本机制想要的目标感。

### 7.5 展示 UI

- `AREA_PREVIEW_COUNT` 3 → **6**，预览轮播从固定 top-3 改为**轮播活跃池全部成员**（保留原有左右轮转动画：三帧可见、左帧转中间、新帧左侧滑入，周期 2.8s）。
- 稀有池成员显示为**纯黑色剪影**，不显示头顶菱形，也不提前公开具体精灵；池内有稀有成员时标题切换为「大量出现!」，明确告诉玩家"本时段有稀客"，驱动立刻出发。
- 新增玩家可见文案（如「大量出现!」）集中在 `src/core/UiStrings.h`，改后须运行 `python3 tools/generate_font16cn.py` 重新生成字形表。

### 7.6 种子与存档

- **活跃池不进存档**：由（时段序号， 区域ID, 重抽计数）派生种子确定性重建，重启后同一时段看到的池不变，SL 刷不了池。
- 存档新增字段：每区域重抽计数 `uint8 × 6`（保底计数见 §7.7 如启用再加 `uint8 × 6`）；结交成功率累积计数（见 §7.9.4）：`uint8 failCount[36]` 共 36 字节（白名单物种索引表）。
- 按项目约定：**存档版本号递增并提供旧档迁移**（旧档迁移时计数填 0）。
- `expeditionSeed` 继续负责趟内其他随机（地图生成、遭遇滚点等），与池种子相互独立。

### 7.7 保底机制（可选，建议启用）

- 同一区域**连续 3 次刷新**稀有槽为 0 → 下一次刷新保底 1 个稀有槽。
- 每区域保底计数 `uint8` 随存档持久化；稀有槽 ≥1 时清零。
- 目的：控制体验下限，防止极端情况下玩家长期见不到稀有亮相，比直接调高槽位概率更可控。

### 7.8 实现要点

- 改动集中在 `ExploreScene`：`RouteMap` 静态表保持不变（仍是全量数据源），场景内新增 `activePoolSpecies[6]` / `activePoolCount` 状态，`rollEncounter()` 改为池内滚点，`loadAreaPreview()` 改为渲染池内容。
- 编译期 `static_assert`（权重和 = 100、等级范围）全部保留不动——校验对象仍是 §三 的全量表。
- 建议同步补主机端测试桩（参照 `tools/*_host.cpp` 体例）：验证池大小分布、稀有槽概率（40/40/20）、池内归一化权重和（含稀有 ×3 加成）、种子确定性（同种子同池）。

### 7.9 稀有精灵结交成功率测算与窗口兑现（v1.2）

> 背景：交友系统（`FriendshipSystem`）与稀有度系统是**相乘**关系——先掷遭遇、再掷结交。
> 本节测算组合后的端到端获得率，并给出兑现窗口承诺的两个配套调整。

#### 7.9.1 结交成功率机制回顾（现状，不改数值）

战胜野怪后触发一次结交判定（`ExploreScene.cpp` 战胜结算 → `FriendshipSystem::passesOfferChecks`）：

```
结交成功率 = 闸门(gate) × 四次晃动(shake)
闸门：150‰ × (1 + 食物羁绊/100)，即羁绊 0 → 15%，羁绊 100 → 30%
晃动：GBA 三代公式，通过率 ≈ odds/255
odds = catchRate × 等级系数 × 状态系数（睡眠/冰冻 ×2，麻痹/中毒等 ×1.5）
总上限 250‰（25%）
```

**稀有精灵（catchRate 45：御三家、伊布家族、迷你龙、快龙、飞天螳螂、耿鬼等）单次战胜结交率：**

| 区域（平均等级） | 裸打（羁绊0，无状态） | 喂食羁绊100 | 羁绊100 + 睡眠/冰冻 |
|------|------|------|------|
| 草地小径 Lv5 | 3.18% | 6.35% | 12.70% |
| 溪桥坡地 Lv12 | 2.88% | 5.76% | 11.53% |
| 高草公园 Lv22 | 2.65% | 5.29% | 10.59% |
| 霜晶洞窟 Lv34 | 2.65% | 5.29% | 10.59% |
| 迷雾森道 Lv47 | 2.35% | 4.71% | 9.41% |
| 古木瀑谷 Lv60 | 2.12% | 4.23% | 8.47% |

对照：常见怪（catchRate 255）裸打 15%、封顶 25%；皮卡丘/鬼斯（190）裸打 11.2%；巨钳螳螂（25）裸打 1.29%、拉满 5.18%。

**结论：交友层数值不动。** 玩家有明确操作杠杆（喂食 ×2 + 睡眠 ×2，合计约 4 倍），稀有比常见难约 5 倍，符合 §4.1 矩阵意图。

#### 7.9.2 端到端获得率测算（以小火龙为例，12 次遭遇/趟）

| 玩法 | 原全表（权重 1%） | 池内窗口（无加成 1.6%） | 池内窗口（×3 加成 4.8%） |
|------|------|------|------|
| 裸打 | 每趟 0.38%（期望 263 趟） | 每趟 0.62%（160 趟） | 每趟 1.83%（55 趟） |
| 喂食羁绊100 | 每趟 0.76%（132 趟） | 每趟 1.24%（81 趟） | 每趟 3.61%（28 趟） |
| 羁绊100+睡眠 | 每趟 1.51%（66 趟） | 每趟 2.47%（40 趟） | 每趟 6.98%（14 趟） |
| 窗口内刷 10 趟收服率 | — | 裸打 6.1% / 拉满 22.1% | 裸打 16.9% / 拉满 **51.6%** |

**问题定位：** 无加成时池内稀有单次遭遇率仅 ~1.6%，一趟期望见到 0.2 次——预览承诺了稀有亮相，玩家刷 5 趟才见到 1 次，且见面后 97% 概率结交失败。双重相乘在这个点上是负体验，需要 §7.9.3 与 §7.9.4 两个兑现手段。

#### 7.9.3 窗口内稀有权重加成（§7.4 的规则，此处定数值）

- 活跃池内 `weight ≤ 3` 的稀有成员，池内滚点权重 **×3**（1→3、2→6、3→9）。
- 示例池 {绿毛虫18、尾立19、铁甲蛹15、拉鲁拉丝8} + {小火龙 1→3}：池内和 63，小火龙单次遭遇率 3/63 ≈ **4.8%**，一趟期望见到 0.57 次。
- 长期守恒校验：折算全周期 26.7% × 4.8% ≈ 1.3%，仅为原表 1% 的 1.3 倍，稀有度基本守恒；如需严格 ≤ 原表，加成降为 ×2（长期 ≈ 0.86%）。

#### 7.9.4 结交成功率累积保底（v1.4 修订）

- **旧机制的问题**：v1.2 的单槽连败计数只记"最近一个目标物种"，交替刷多个物种时计数互相清零，保底永远兑现不了。
- **新机制：按物种独立累积成功率。** 被追踪物种每次结交判定失败 → 该物种 `failCount +1`（上限 **5 层**）；该物种后续结交判定获得 **+3pp × failCount** 的成功率加成（最多 **+15pp**），叠加在 §7.9.1 闸门×晃动结果之上、250‰ 总上限之前结算。结交成功 → **仅该物种**计数清零，不影响其他物种的累积。
- **追踪白名单**：§4.1「较少」及以上稀有度（较少/稀有/非常稀有/极稀有）的全部野生精灵，加特殊精灵（卡比兽、梦幻、拉帝亚斯、拉帝欧斯），共 **36 个物种**。常见/普通档不记录——其基础结交率 11%~25% 本就不存在"十连跑"问题，不记录还能压缩存档体积。
- **数值论证**：稀有档（catchRate 45）基础约 5% → 5 连败后约 20%，仍低于常见怪 25% 的结交上限，**平均获得率数量级不变**；消除的是"同一物种连败 streak"，而非普遍提速。神兽幻兽的遭遇为一次性事件，计数**跨事件保留**，直到收服为止。
- **存档**：编译期建立白名单 物种→索引（0~35）映射表，存档持久化 `uint8 failCount[36]` 共 **36 字节**，替代 v1.2 的 3 字节单槽字段；存档版本号递增，旧档迁移时全部填 0。

#### 7.9.5 其他出口（现状，无需改动）

- 区域头目战：Boss 结交走 `BOSS_ODDS_PERCENT = 60` 的独立系数，是稳定的定向获取途径。
- ESP-NOW 交换：已有联机基础，作为稀有获取的社交出口，分流纯刷压力。

## 八、特殊精灵与游荡机制 v1.3

> 机制定位：让中后期区域拥有明确的代表性特殊精灵，并在通关后形成跨区域追踪玩法。  
> 特殊精灵走独立调度层，不加入 §三的普通遭遇表，也不占用 §七的活跃池槽位，因此六个区域的权重和仍保持 100。

### 8.1 特殊精灵分布

| 区域 | 特殊精灵 | 定位 | 等级 | 首次登场规则 |
|------|---------|------|------|-------------|
| **高草园**（区域3） | #143 卡比兽 | 区域特色头目 | Lv.27 | 最终区段保证出现，直到首次击败 |
| **雾林径**（区域5） | #380 拉帝亚斯 | 区域传说头目 | Lv.53 | 最终区段保证出现，直到首次击败 |
| **雾林径**（区域5） | #151 梦幻 | 幻影事件 | Lv.70 | 拉帝兄妹均首次击败后解锁 |
| **古瀑谷**（区域6） | #381 拉帝欧斯 | 区域传说头目 | Lv.67 | 最终区段保证出现，直到首次击败 |

“首次完成”统一以**首次击败**为判定。战败或逃跑不会解锁后续阶段，对应特殊头目在下一趟探索中继续保证出现。

### 8.2 卡比兽规则

- 卡比兽作为高草园的特色头目，首次到达该区域最终区段时直接替代普通区域头目。
- 首次击败前，每趟高草园探索都保证卡比兽登场，避免当前“40% 头目出现率 × 25% 候选概率 = 10% 单趟概率”导致长期看不到内容。
- 首次击败后取消保证，卡比兽回到高草园普通头目候选池。
- 后续沿用现有区域头目调度：头目出现率 40%，卡比兽占 4 个候选之一，单趟重复遭遇率约 10%。
- 卡比兽不是唯一精灵，首次及后续头目战均允许触发正常结交流程。
- 经验倍率和金币奖励沿用区域头目规则：经验 200%，胜利额外获得 10 金币。

### 8.3 拉帝亚斯与拉帝欧斯首次头目战

- 拉帝亚斯固定为雾林径首次传说头目，拉帝欧斯固定为古瀑谷首次传说头目。
- 首次击败前，它们优先于该区域的普通头目，在最终区段保证登场。
- 首次头目战用于完成区域挑战，**不触发结交**；首次击败后才解锁对应精灵的游荡状态。
- 首次击败后，该区域恢复原有普通头目候选表，拉帝兄妹不加入普通头目候选池。
- 两只精灵分别解锁，击败拉帝亚斯不要求已经击败拉帝欧斯，反之亦然。

### 8.4 游荡机制

首次击败对应传说头目后，该精灵开始在六个区域间游荡：

1. 拉帝亚斯和拉帝欧斯分别拥有独立的游荡位置与迁移计数。
2. 游荡位置可落在全部六个区域，包括低等级区域。
3. 位置由“8 小时时段序号、物种编号、迁移计数”确定性生成，重启和读档不会改变当前位置。
4. 拉帝亚斯和拉帝欧斯的游荡战等级均固定为 **Lv.70**，不随所在区域等级变化。
5. 游荡战允许触发结交，并继续使用现有 Boss 结交系数及 §7.9.4 连败保底。
6. 游荡战结束后，无论胜利、战败或逃跑，迁移计数都加 1，精灵立即移动到另一随机区域并存档。
7. 新位置不得与上一位置相同；两只游荡精灵计算到同一区域时，后计算的一只顺延到下一区域。
8. 同一趟探索最多出现一只游荡精灵，避免连续传说战挤占正常探索节奏。
9. 玩家探索其当前所在区域时，可在最终区段选择挑战或绕开；游荡精灵不得阻塞探索出口。

游荡位置不直接使用运行时随机数，建议按以下方式派生：

```cpp
slotIndex = gameMinutesTotal / 480;
seed = mix(slotIndex, speciesId, roamingRerollCount);
area = seed % EXPLORE_AREA_COUNT;
```

若计算结果等于上一位置，则使用种子的下一段哈希结果重抽；发生双精灵位置冲突时，对后计算者使用 `(area + 1) % EXPLORE_AREA_COUNT`。

### 8.5 梦幻幻影事件

- 梦幻不作为区域头目，也不加入普通活跃池，避免受到“稀有成员池内权重 ×3”影响而出现率过高。
- 拉帝亚斯和拉帝欧斯均首次击败后，才解锁梦幻事件，作为完成区域5、6主线后的回访目标。
- 每个 8 小时时段，雾林径有 **20%** 概率出现“神秘踪迹”。
- 神秘踪迹同样由时段种子确定性生成；同一时段重启或读档不会改变结果。
- 神秘踪迹活跃时，梦幻以固定 **Lv.70** 在雾林径深层作为独立事件登场；同一时段可重复探索，为低结交率提供多次尝试机会。
- 梦幻事件允许玩家选择挑战或绕开，不阻塞探索出口。
- 梦幻允许触发正常结交与 §7.9.4 连败保底。
- 队伍或通讯录中已经存在梦幻时，不再触发保证事件；删除该联系方式后允许重新触发，避免永久绝版。

### 8.6 活跃池与菜单展示

- 普通精灵继续使用 §七的 4 ~ 6 只活跃池，遭遇与“栖息精灵”预览保持一致。
- 卡比兽、拉帝兄妹和梦幻不计入活跃池数量，也不参与普通遭遇权重归一化。
- 未发现的特殊精灵不直接显示正面图，避免菜单提前泄露内容。
- 当前区域存在首次特殊头目、游荡精灵或梦幻踪迹时，地图名称改为**明亮青色** `RGB(72, 220, 255)`，不额外增加菱形或感叹号。
- 普通未选中名称保持灰色，普通已选中名称保持黄色。
- 特殊活动地图无论是否选中，名称均保持明亮青色；选中状态继续由左侧黄色游标条表达，避免颜色承担两个含义。
- 特殊精灵迁移或活动时段结束后，旧地图名称立即恢复普通颜色，新活动地图名称同步变亮。
- 名称变色只表示“存在特殊活动”，不直接泄露具体物种，也不把特殊精灵加入“栖息精灵”轮播。

### 8.7 事件调度优先级

同一趟探索只能调度一个最终区段特殊事件，优先级固定为：

```text
首次特殊头目
> 游荡拉帝
> 梦幻幻影事件
> 普通区域头目
> 普通拾取或遭遇事件
```

- 首次特殊头目存在时，不掷普通头目出现率。
- 游荡精灵命中当前区域时，覆盖该趟普通区域头目。
- 梦幻踪迹与游荡精灵同时命中雾林径时，优先游荡精灵；梦幻事件保留到同一时段的下一趟探索。
- 最终路径无法放置头目时，不消费首次击败状态或迁移计数，下一趟继续尝试。

### 8.8 存档设计

建议在 `GameState` 增加：

```cpp
// bit0=卡比兽，bit1=拉帝亚斯，bit2=拉帝欧斯
uint8_t specialBossDefeatedMask = 0;

// [0]=拉帝亚斯，[1]=拉帝欧斯；每次游荡战结束后递增
uint8_t roamingRerollCounts[2] = {};
```

- 游荡位置由确定性种子实时重建，不直接存储区域编号。
- 是否已取得特殊精灵联系方式，通过扫描队伍和通讯录中的 `speciesId` 判断，不新增重复字段。
- 修改后提升 `SAVE_VERSION`，旧档迁移时上述字段清零。
- 首次特殊头目击败、游荡迁移后使用重要存档等级立即写入，避免掉电造成位置回滚。

### 8.9 实现边界

建议新增纯数据模块 `ExploreSpecialEncounter.h`，不要继续扩大 `ExploreBoss.h` 的普通候选表职责：

- `ExploreBoss.h`：保留普通区域头目概率、候选和奖励。
- `ExploreSpecialEncounter.h`：保存卡比兽、拉帝兄妹、梦幻的区域、等级、解锁条件和事件优先级。
- `ExploreScene::generateMapBlocks()`：生成本趟普通头目后，再由特殊调度层决定是否覆盖。
- `ExploreScene::finishWildFaint()`：首次特殊头目写入击败标记；游荡战进入结交与迁移流程。
- `ExploreScene::loadAreaPreview()`：只预览普通活跃池；特殊踪迹使用独立标识。

### 8.10 测试与验收

主机端测试至少覆盖：

1. 未击败卡比兽时，高草园最终区段始终调度卡比兽。
2. 战败或逃跑不会写入首次击败标记。
3. 首次击败拉帝亚斯、拉帝欧斯后分别解锁游荡，首次头目战不触发结交。
4. 相同存档状态和相同时段得到相同游荡区域，重启不可刷新位置。
5. 拉帝兄妹游荡战和梦幻幻影事件均固定为 Lv.70，不受区域等级影响。
6. 两只游荡精灵不会占用同一区域，同一趟最多出现一只。
7. 梦幻只在拉帝兄妹均击败后参与 20% 时段判定。
8. 梦幻、拉帝兄妹和卡比兽不进入普通活跃池，不改变各区域遭遇权重和。
9. 特殊事件优先级符合 §8.7，路径无法放置时不消费状态。
10. 存档迁移后新增字段为 0，特殊头目击败和游荡迁移可正确持久化。
11. 游荡战任意结束方式都会迁移，且新区域不同于旧区域。
12. 特殊活动地图名称使用明亮青色，选中时名称不变色且黄色游标仍可见。
13. 所有 Lv.70 特殊战均可绕开，不会阻塞探索出口。
