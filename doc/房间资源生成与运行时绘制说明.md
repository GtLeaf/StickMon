# 房间资源生成与运行时绘制说明

本文说明 StickMon 当前房间背景资源从编辑器导出到固件运行时绘制的完整链路。

## 总览

当前固件不会在运行时读取 `room_layout.json`。

`room_layout.json` 是编辑期和生成期的数据源。项目通过 Python 脚本读取它，离线合成房间图和交互元数据，写入 `standard.smonroom`。固件运行时只读取房间包，不解析 JSON。

```text
tools/room_editor
  -> origin_asset/room/standar/room_layout.json
  -> tools/prepare_room_background.py
  -> data/packs/dev/rooms/standard.smonroom
  -> src/core/RoomResource.cpp
  -> src/core/RoomRenderer.cpp
```

## 数据源

主数据源：

```text
origin_asset/room/standar/room_layout.json
```

它通常由 `tools/room_editor` 导出，包含：

- `backgroundLayers`：房间背景层，含 day/night 可见性。
- `backgrounds`：主背景元数据和裁剪信息，保留兼容用途。
- `furniture`：家具实例、坐标、尺寸、day/night 可见性、阴影参数。
- `roomGeometry`：墙面、地板、可行走区域等标注面。
- `night`：白天/夜晚光源与投影配置。
- `guides`：编辑器辅助线，主要用于预览。

生成脚本还会读取家具图片目录：

```text
origin_asset/room/forniture
```

## 生成命令

更新 `room_layout.json` 或相关图片后，运行：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 tools/prepare_room_background.py \
  --layout origin_asset/room/standar/room_layout.json
```

脚本默认会输出：

```text
origin_asset/generated/room/standard_room_day_240.png
origin_asset/generated/room/standard_room_night_240.png
origin_asset/generated/room/standard_room_day_480.png
origin_asset/generated/room/standard_room_night_480.png
origin_asset/generated/room/standard_room_240.png
origin_asset/generated/room/standard_room_day_source.png
origin_asset/generated/room/standard_room_night_source.png
src/assets/RoomAssets.h
src/assets/RoomAssets.cpp
```

`standard_room_240.png` 是白天图的兼容副本。`*_480.png` 是按高分辨率原始底图和家具重新合成的 AMOLED 房间图，不是对最终 `240x161` 图的最近邻放大。

## 生成内容

`tools/prepare_room_background.py` 会先把 `room_layout.json` 转成两张最终房间图：

- day 图：背景层 + day 可见家具 + day 投影。
- night 图：背景层 + night 可见家具 + night 投影。

随后生成 `data/packs/dev/rooms/standard.smonroom` v4 房间包：

- 世界尺寸固定为 `240x161`，行走区域、床、碗、门和行为锚点都继续使用世界坐标。
- 背景美术尺寸为 `480x322`，day 作为 RGB565 raw deflate base。
- night 只保存相对 day 的差异行段和 RGB565 像素。
- 包头同时记录世界尺寸、美术尺寸和资源倍率，避免用背景尺寸污染行为逻辑。

当前资源示例：

```text
world = 240x161
art = 480x322
base raw = 309120 bytes
base compressed = 99120 bytes
night patch = 290 runs / 6919 pixels
room pack = 116046 bytes
```

旧 v3 房间包仍可读取；旧包会被视为 `art = world` 的 `1x` 资源。

## Patch 格式

房间包中的 patch run 定义为：

```cpp
struct RoomPatchRun {
    uint16_t y;
    uint16_t x;
    uint16_t len;
    uint32_t colorOffset;
};
```

含义：

- `y`：高分辨率美术图中的差异行。
- `x`：该行差异段起点。
- `len`：该段连续差异像素数。
- `colorOffset`：该段在 `STANDARD_ROOM_NIGHT_PATCH_PIXELS` 中的起始索引。

运行时把 base 解码到 PSRAM 后，按这些 run 将 night 差异像素覆盖到对应位置。

## 运行时绘制

运行时代码位于 `src/core/RoomResource.cpp` 和 `src/core/RoomRenderer.cpp`，AMOLED 主界面入口位于 `firmware/amoled_1_8_v1/main/HomeScreen.cpp`。

主要流程：

1. `RoomResource::loadExternal()` 读取包头，分离世界尺寸和美术尺寸。
2. `RoomRenderer::prepare(night)` 检查当前 PSRAM 房间缓存是否已经是目标模式。
3. 如果缓存不存在或 day/night 模式变化：
   - 解码 base 到 PSRAM。
   - 如果是 night，再叠加 night patch。
4. AMOLED 主界面使用 `480x322` 美术图，按 `cameraX/cameraY` 乘资源倍率直接裁剪到 `368x296` 房间视口；不再用 `2x2 fillRect` 放大房间像素。
5. M5StickS3 和其他旧调用按目标输出倍率做最近邻采样，世界坐标与交互逻辑不变。

房间缓存大小：

```text
480 * 322 * 2 = 309120 bytes
```

该缓存只在运行时分配到 PSRAM，不计入静态 RAM。

如果 PSRAM 不可用，代码会降级为：

1. 每帧直接绘制 base RLE。
2. 夜晚时逐像素叠加 night patch。

这样可以避免占用内部 RAM 的约 302 KB 缓冲。

## 为什么不用运行时读取 JSON

StickMon 当前不把 `room_layout.json` 放入文件系统并在运行时解析，原因是：

- JSON 解析会增加固件代码体积和运行时复杂度。
- 房间图最终需要转成 RGB565 像素数据，运行时解析 JSON 仍然不能绕开图片合成问题。
- 当前房间内容不需要玩家动态编辑，离线生成 C++ 常量更稳定。
- 交互点、可行走区域等数据在编译期固定后，逻辑更简单。

因此当前策略是：

```text
编辑期 JSON -> 离线生成 C++ -> 固件运行时直接绘制
```

## 体积收益

当前方案只向固件资源分区写入 `standard.smonroom` 一份房间背景包；`240x161` 和 `480x322` PNG 是生成期预览/调试产物，不会各自作为固件资源重复刷入。

AMOLED 主界面每行直接发送已经解码的高分辨率像素，减少房间绘制时的大量 `fillRect` 调用；房间背景清晰度和横纵向相机滚动范围同时保留。

## 修改房间后的更新流程

修改房间资源时建议按这个顺序：

1. 在 `tools/room_editor` 中导入/调整背景、家具、房间面和 day/night 可见性。
2. 导出新的 `room_layout.json` 到：

   ```text
   origin_asset/room/standar/room_layout.json
   ```

3. 运行：

   ```bash
   PYTHONDONTWRITEBYTECODE=1 python3 tools/prepare_room_background.py \
     --layout origin_asset/room/standar/room_layout.json
   ```

4. 检查脚本输出中的：

   ```text
   base_rle_words=...
   night_patch_runs=...
   night_patch_pixels=...
   shared_rle=...
   ```

5. 构建验证：

   ```bash
   pio run -e m5stick-s3
   ```

## 注意事项

- 如果 day/night 最终合成图完全一致，`night_patch_runs` 和 `night_patch_pixels` 会接近 0。
- 如果只有背景层相同，但 day/night 家具或投影不同，仍会生成 night patch。
- 如果 day/night 差异区域变大，patch 体积会增长；极端情况下可能接近完整 night 图。
- 当前 base 固定使用 day 最终图。night 是 day 的 patch。
- `room_layout.json` 改动后，如果没有重新运行生成脚本，固件不会变化。
- `origin_asset/generated/room/*.png` 是检查用预览和生成副产物，不是运行时直接读取的文件。
- 家具库唯一来源是 `tools/room_editor/generated/furniture_library/`；不要在
  `origin_asset/generated/room` 下维护镜像副本。
