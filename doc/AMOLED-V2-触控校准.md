# AMOLED V2 触控校准

日期：2026-10-19。硬件为本次连接的 CO5300 / CST820 V2；不使用此前物理
V1 的九点测量替代 V2 数据。源代码与完整坐标表见 V2 README 和
`tools/amoled_v2_touch_host.cpp`。

## 原因与实现

旧 V2 固件无条件使用旧物理 V1 / FT 控制器的拟合参数，导致真实 CST820
触点往边缘扩散并被裁剪。当前按控制器地址选择独立参数：

- CST820 `0x15`：`x=round(rawX*0.90673230+13.937319)`，
  `y=round(rawY*0.88606005+20.206188)`。
- FT 兼容 `0x38`：保留既有拟合与回放结果，供旧物理 V1 运行此固件时使用。

探测优先级和官方 BSP 保持一致，CST 优先；在构造触控驱动前探测，避免
驱动启动后控制器休眠造成误判。总线初始化、句柄、地址探测失败均返回
错误；启动日志明确输出实际选择的 profile。未修改 managed component、
V1 目标驱动、显示对齐、资源包或游戏存档格式。

## 两轮实测

第一轮为重测后的九个 DOWN 点，时间戳 139570–147506。此前误点菜单控件
产生的样本被重测清除，未参与拟合。仅使用原始 DOWN 坐标拟合，UP 保留
用于检查拖动和诊断，不混入同一落点统计。

第一轮旧映射平均误差 32.0 像素、最大 39.4 像素；首版 CST 拟合回放为
10.7 / 25.6 像素。刷入首版后独立采集第二轮九点，时间戳
102943–109885，实测平均误差 13.5 像素、最大 23.3 像素；用户反馈
“已点完，更贴近手指了”。

最终参数合并两轮 18 点做独立轴最小二乘，减少对单次落点的依赖。
18 点回放平均误差 10.9 像素、最大 28.1 像素，旧 FT 参数在相同 18 点上的
平均误差为 32.7 像素、最大 41.9 像素。最终参数在第一轮上为
10.7 / 28.1 像素，在第二轮上为 11.1 / 19.7 像素。
这些最终数字属于拟合残差；第二轮参与最终参数拟合后，不能再称作最终
参数的独立验收。用户的改善反馈对应合并前首版参数。

原始临时日志：`/tmp/stickmon-v2-calibration-raw.log`、
`/tmp/stickmon-v2-calibration-validation.log`。

## 验证与边界

`python3 tools/test_amoled_v2_touch.py` 编译真实 TouchInput 实现，验证 FT
历史回放、CST 两轮回放、CST-only / FT-only / 两地址均存在时的选择、
探测失败、坐标单调性、释放事件及中断唤醒行为。布局源码检查 5 项通过。

刷机只更新应用分区，未擦除或覆盖 NVS。刷入前备份了当前新 V2 自身的
0x6000 字节 NVS，没有使用旧 V1 备份。校准页只采样，不会自动持久化
用户校准；参数随固件生效。

最终 Lite Debug、Lite Release、Claw Release 均构建成功，两个 Release
打包完成；最终 Lite Debug 已刷入当前新 V2。重启日志确认
`Touch calibration profile: CST820 (0x15)`，串口诊断正常，RAM 与 NVS 的
金币、队伍、仓库、HP、等级和道具字段与刷入前一致。最终启动检查日志为
`/tmp/stickmon-v2-calibration-final-boot.log`，串口采集已关闭。

目前采样中多次出现 rawY=447，右侧采样也有 rawX=367，边缘是否存在
饱和以及可重复性仍需更多物理测量。线性拟合不能恢复传感器已丢失的
位置信息，也不能保证所有点都达到平均误差；未通过补丁强行吸附到边缘
或将拟合残差表述为全屏精度。若继续追求更高精度，应固定点触方式、
重复采样并额外检查物理边缘，先区分落点差异与传感器饱和。
