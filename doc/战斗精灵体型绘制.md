# AMOLED 战斗精灵体型

2026-10-19。

AMOLED 战斗正面图按源画稿在共同画布中的占比显示，不再统一调整到约
96 像素高。卡比兽也走共同规则，不再单独指定目标高度。

`tools/generate_pokemon_sprites.py` 读取 Front 源图，裁出可见范围，再按
源画布宽高归一到 160×160，生成 `src/assets/PokemonBattleSizes.h`。
表中记录的是画稿占比，不是图鉴身高；不同姿势、翅膀和尾巴属于轮廓的一部分。

更新尺寸表：

```sh
python3 tools/generate_pokemon_sprites.py --battle-sizes-only
```

完整精灵资源生成也会同步更新该表。单独更新尺寸表不重写 `.smonsp`，
不修改资源格式或存档。现有 FRONT 被探索预览等界面共用，保持它们原来的资源尺寸，
只在战斗表现中恢复源画稿的相对大小。

`ui/BattleSpriteLayout.h` 根据记录的自然宽高和当前载入帧计算等比缩放，
仅在超出战斗区域时缩小。区域上限为宽 176、高 144 像素，悬浮高度占用
这 144 像素的预算。敌方图按可见身体在可用区域中垂直居中，透明地面留白
不计入身体高度；体型越小，向上调整越多，避免全部贴着底边而上方过空。
普通精灵的视觉中心约为 (272,157)，飞行精灵在扣除悬浮预算后居中。
例如高 66 像素的妙蛙种子向上调整 39 像素；占满区域的大体型保持原位置。
正常敌方中心 x=272、区域底边 y=229，身体上缘不越过
y=85，右缘不越过 x=360，预留 8 像素受击抖动；攻击向左移动也保留在屏内。
实际绘制边界同时提供给命中特效，敌方命中点取身体中心；异常状态特效也
同步应用垂直位移，避免居中后特效仍停留在旧位置。

玩家背面图维持独立的近景构图规则。未登记物种使用载入帧的原始倍率并执行
相同边界裁限；缺图时沿用占位图。

验证包括源图画布归一、生成表一致性、全部登记物种的真实帧尺寸与悬浮边界，
以及 16 种代表精灵的全屏/局部刷新像素对照和攻击/受击场景：

```sh
python3 tools/test_generate_pokemon_sprites.py
python3 tools/test_amoled_native_render.py
python3 tools/test_amoled_battle.py
```

设计参考：绿宝石 `pret/pokeemerald` 的共同 64×64 画布和物种垂直偏移。
本项目沿用自己的 Essentials 画稿、竖屏布局和悬浮参数，不直接套用原版坐标。
