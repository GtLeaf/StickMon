# StickS3 电子宠物机 · 玩法与技术设计文档 v0\.1

**项目目标**：基于 M5Stack StickS3（ESP32\-S3 \+ 1\.14" LCD \+ IMU \+ Mic/Speaker \+ IR TX/RX \+ Wi\-Fi/BLE \+ 250 mAh 电池）打造一台「宝可梦 × 拓麻歌子」融合的便携电子宠物机，支持养成、捕捉、对战、设备互联、通讯进化。

---

# 一、设计理念

|维度|取舍|
|---|---|
|拓麻歌子的「养成陪伴」|携带在身边，有饥饿/心情/疲劳，需要互动|
|宝可梦的「策略对战」|属性克制、四技能、PP、命中率、经验升级、进化|
|StickS3 形态约束|屏幕 135×240、两个按键、磁吸便携、IR/ESP\-NOW 双通道|

**核心设计原则：**

1. **离线优先**：所有玩法在断网状态下仍可运行；Wi\-Fi 仅用于活动/同步。

2. **小数据集**：受限于 8 MB Flash，不追求全图鉴，**首发 30\~50 只人气精灵**即可承载完整体验。

3. **双通道互联**：近距离面对面 → IR；房间内多人 → ESP\-NOW。

## 4\.2 战斗公式（简化版宝可梦）

```Plain Text
伤害 = ((2*Lv/5 + 2) * 威力 * Atk/Def) / 50 + 2
     × STAB(1.5) × 属性倍率 × 随机数(0.85~1.0) × 暴击(1.5)

```

- 等级上限 50（节省 EXP 表大小）

- 每只精灵仅 **1 个普攻 \+ 1 个特殊技能**；特殊技能由熟练度 / 亲密度 / 麦克风音量等因素**概率触发**（详见 §4\.4）

- 状态：中毒 / 麻痹 / 睡眠 / 灼伤 / 冰冻 / 混乱（用 1 个 uint8 位字段表达）

## 4\.3 战斗节奏

- 单选指令制，每回合 ≤ 5 秒

- 回合动画限制在 1\.5 s 内，照顾 StickS3 屏幕尺寸

- 失败不死亡，HP 归零进入「濒死」状态，需回中心或喂药；**战斗仅 1v1，不支持中途换宠**

## 4\.4 技能与触发系统（轻量化设计）

为契合 StickS3 屏幕与按键的极简形态，每只精灵**仅持有 2 个技能槽**：

|技能槽|类型|说明|
|---|---|---|
|普攻|本系物理 / 特殊|固定可用，PP 无限，威力 40\~50；玩家选「攻击」即必发|
|特殊技能|招牌技 / 大招|威力 80\~120 或带状态附加，**不能主动选择，仅按概率触发**|

### 4\.4\.1 触发概率公式

```Plain Text
P_special = base + w1*proficiency_norm + w2*affection_norm + w3*mic_norm + w4*hp_low_bonus

其中：
  base              = 0.05               // 5% 基础保底
  proficiency_norm  = 普攻使用次数 / 100   // 0~1，封顶 1
  affection_norm    = 亲密度 / 255         // 0~1
  mic_norm          = 当回合 Mic 峰值 dB 归一化 / 1
  hp_low_bonus      = HP < 30%? 0.15 : 0  // 残血爆发

  w1=0.20  w2=0.25  w3=0.20  w4=1.0
  P_special 上限封顶 0.85，避免必发

```

### 4\.4\.2 四个驱动因子

- **熟练度（proficiency）**：每只精灵单独记录，每次普攻命中 \+1，封顶 100。鼓励「养成自己的精灵」而非来回换队

- **亲密度（affection）**：与拓麻歌子层共享，0\~255。携带、喂食、不濒死会涨；濒死会掉

- **麦克风（mic）**：选择攻击指令时，**对设备喊一声**（如「上！」）→ 采样 0\.5 s 峰值音量 → 归一化 0\~1 作为本回合加成；不喊也能玩，仅普攻

- **残血爆发（hp\_low\_bonus）**：HP 低于 30% 时额外 \+15%，致敬「绝处逢生」桥段

### 4\.4\.3 触发反馈

- 普攻：精灵小幅前冲 \+ 普通音效

- 特殊触发：屏幕短暂闪烁 \+ 招式名横幅滑入 \+ 招牌音效（每只精灵独立录制）\+ 全屏特效 1\.0 s

- 麦克风触发加成生效时，HUD 出现一个跳动的 🎙 图标，强化「喊出来真的有用」的反馈

### 4\.4\.4 设计动机

- **降低操作复杂度**：两键设备无需在 4 个技能里挑选，直接「打」即可

- **放大养成价值**：熟练度 \+ 亲密度让玩家觉得「我的皮卡丘和别人的不一样」

- **利用硬件特色**：Mic 不只是装饰，是真实战斗输入

- **制造高光时刻**：低概率招牌技触发的瞬间是整个对战最爽的反馈点

## 4\.5 濒死与轮换机制

### 4\.5\.1 状态定义

|状态|触发|解除|
|---|---|---|
|`ALIVE`|HP \> 0|—|
|`FAINTED`|HP = 0|在队伍 / 仓库静养 **24 真实小时** 后自动恢复至 100% HP|
|`OUT_OF_PARTY`|全队濒死|退出探索 / 战斗，回主界面|

### 4\.5\.2 战斗中濒死流程（PvE / PvP）

```Plain Text
出战精灵 HP=0
  ↓
[FAINT 动画 1.5s + 葬礼音 + 黑屏 0.3s]
  ↓
扫描队伍剩余可战斗精灵 (state==ALIVE && hp>0)
  ↓
├─ 找到 ≥1 只 → 弹「派出 XXX？」选择器（B 切换 / A 确认）
│      ↓ A
│      [新精灵入场动画 1.0s] → 战斗继续，对手保留剩余 HP
│
└─ 全队濒死 → 弹「全员力尽…」
              ↓ A
              [传送回主界面动画 2.0s] → 当前探险终止
              野生战斗：原对手按"逃跑"处理，无 EXP / Coin
              PvP 战斗：判负，按 §16.1.5 结算

```

> **关键约束**：濒死轮换不消耗回合（与原作不同），降低两键设备的操作负担。新精灵入场即可行动，但 mic 加成需重新采样。

### 4\.5\.3 24h 静养恢复

```Plain Text
// 每 5 min RTC 唤醒一次，扫描所有精灵
void faint_recovery_tick(void) {
    uint32_t now = rtc_unix();
    for (auto& p : team_and_storage) {

}
```

## 4\.6 濒死 EXP 不扣减

- 当前出战 KO 后队列空 → 立即 BATTLE\_END，winner = 对方设计取舍：本期不实现负反馈式扣 EXP；濒死的代价已经足够（24h 静养 \+ 亲密度 \-5 \+ mood \-10），再扣 EXP 会让玩家挫败感过强。

- EXP / Coin 按 §7\.3\.1 BattleEnd 结构正常结算

- 不额外扣亲密度（PvP 默认 ranked 不计入 PvE 亲密度）

# 五、探险系统（捕捉 \+ 随机事件）

4. **遭遇触发**：

- 计步达到阈值（IMU 累计加速度积分） → 草丛遭遇

- 麦克风捕获到环境噪声峰值 → 触发隐藏精灵

- 扫到附近 ESP\-NOW 广播信标 → 触发玩家共鸣事件

5. **战斗削弱**：先打弱对方 HP / 上状态

### 6\.7\.2 三因子积分模型

```Plain Text
// 每次 IMU/Mic 事件都加权累计到三个 score 桶
struct StarterScore {
    int32_t fire_score;   // 火 = 摇晃越剧烈、声音越大
    int32_t water_score;  // 水 = 轻柔抚摸、节奏稳定
    int32_t grass_score;  // 草 = 静置陪伴、柔声细语
};

// 采样规则（180s 窗口内每 100ms 一次）
// IMU 加速度峰值 > 2.0g  → fire_score   += 5
// IMU 加速度峰值 0.3-1.0g（节奏摇）→ water_score += 3
// IMU 静止（< 0.1g）连续 1s → grass_score += 2
// Mic 峰值 > 70 dB        → fire_score   += 4
// Mic 平均 40-60 dB（说话）→ water_score += 3
// Mic < 30 dB（安静）连续 5s → grass_score += 4

// 最终判定：argmax(scores)，三者全平 → 默认草系
PokemonId pick_starter(StarterScore s) {
    if (s.fire_score >= s.water_score && s.fire_score >= s.grass_score)
        return STARTER_FIRE;   // 小火龙
    if (s.water_score >= s.grass_score)
        return STARTER_WATER;  // 杰尼龟
    return STARTER_GRASS;       // 妙蛙种子
}

```

## 12\.2 心情值持久化方案

### 12\.2\.1 推荐方案 B：影子状态 \+ 节流落盘 \+ 重算函数

系统设置\(亮度、音量、配对、表盘等\)的落盘字段与默认值。

```Plain Text
// === RAM 中的实时心情（每帧可读）===
typedef struct {
    int16_t  mood_raw;     // -100 ~ +100，可越界缓冲
    uint32_t last_save_ts;
    uint8_t  dirty;        // 任何因子变化即置 1
} MoodShadow;

// === 心情值实时计算公式（与 UI §1.4 对齐）===
//   mood = clamp(
//       40                              // 基础值
//     + (affection / 255) * 30          // 亲密度贡献 ±30
//     + (satiety  / 100) * 15           // 饱食度贡献 +15
//     + (hp_cur / hp_max) * 15          // HP 占比贡献 +15
//     - hours_since_last_play * 2       // 24h 没碰 → -48
//     - faint_count_today * 10          // 每次濒死 -10
//   , 0, 100)

// === 落盘策略 ===
#define MOOD_SAVE_INTERVAL_S 300   // 5 分钟节流
#define MOOD_SAVE_THRESHOLD  10    // mood 变化 > 10 立即落盘

void mood_tick(PokemonRuntime* p) {
    int16_t now_mood = mood_recompute(p);
    if (abs(now_mood - p->mood) > MOOD_SAVE_THRESHOLD ||
        rtc_unix() - shadow.last_save_ts > MOOD_SAVE_INTERVAL_S) {
        p->mood = clamp(now_mood, 0, 100);
        nvs_save_runtime(p);
        shadow.last_save_ts = rtc_unix();
    }
}

```

### 12\.2\.3 长期写入磨损评估

- 每 5 分钟自动落盘 \+ 关键事件即时落盘（捕获 / 进化 / 对战胜负）

```Plain Text
NVS 单页擦写寿命 = 100,000 次
节流后写入频率   = 300 次/天 × 365 天 = 109,500 次/年
NVS 内置磨损均衡 → 实际单页 ≈ 1/N（N = 24KB / 1KB 块数 = 24 块）
预期使用寿命     ≈ 24 × (100000 / 109500) ≈ 22 年

```

- 防丢失：双 Buffer 轮替写入，配 CRC32 校验

> 满足"消费电子 5–10 年"目标 4 倍以上，安全。

### 12\.5\.4 6 步握手（含 SAS 4 位防中间人）

```Plain Text
A → broadcast: HELLO {device_id, pubkey_a, nonce_a}
B → unicast(A): HELLO_ACK {device_id, pubkey_b, nonce_b, sas_choice}
两端独立计算: shared_key = ECDH(privkey, peer_pubkey)
              session_id = sha256(nonce_a||nonce_b)[:2]
              sas_4digit = sha256(shared_key)[:4]   显示给玩家
玩家屏幕同时显示 4 位数字 → 双方按 A 确认一致 → 握手完成
A → B: SESSION_OK
B → A: SESSION_OK_ACK
进入应用层 (BATTLE / TRADE / EVOLVE)

```
