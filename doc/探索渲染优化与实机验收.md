# 探索渲染优化与实机验收

2026-10-14，微雪 AMOLED V2；V1 复用同一套应用和 UI。本轮实现位置刷新与走路动画解耦、静止镜头下的局部矩形刷新。

## 实现

- `updateExploreRoute` 每次移动更新都会请求位置刷新，走路精灵图仍按 90ms 换帧；不再等待换帧才显示新的位置。暂停探索仍不持续刷新。
- 动态刷新范围取上次绘制和当前精灵范围的并集，包含领队、跟随精灵、浮空偏移和阴影；按实际帧尺寸计算，替代原来精灵上下各 120 像素的全宽条带。
- 应用合并矩形脏区；普通按行刷新会扩展为全宽。页面裁剪、世界地图缓存的背景恢复、草丛遮挡和板级传屏均使用同一个横向范围。V1/V2 使用已有矩形传屏路径，锁屏原有按行强制刷新保留。
- 镜头变化时刷新全部地图区域 `0..344`；场景切换和淡入淡出继续完整刷新。每 10 步回复 HP 后明确刷新底部状态区。

## 验证

Debug native 40 项测试通过，新增逐像素对比覆盖 20ms 内位置刷新但未换动画帧、四方向、不同体型和浮空精灵、跟随精灵停止、阴影、草丛遮挡、镜头滚动及暂停。局部刷新与同一时刻的完整画面一致，脏区外像素未被修改。探索页面 18 项、探索步进 14 项、锁屏 6 项、渲染调度 2 项检查通过；V1/V2 Claw Debug 构建通过。

V2 刷入应用和当前资源包，均通过设备哈希校验；分区表与构建一致，启动槽为 ota_0。刷入前已备份配置与存档，没有覆盖 NVS。通过 `diag explore 0` 走正常出门、自动战斗、拾取和回房流程，进行了两轮实机探索。

| 采样情况 | 结果 |
| --- | --- |
| 两轮常规约一秒窗口 | 44 个窗口，1322 帧 / 44.970435 秒，平均 29.40 FPS |
| 完全使用局部矩形的两个静止镜头窗口 | 48、50 FPS；传屏间隔约 20ms |
| 常规镜头滚动窗口 | 约 19.6 FPS |
| 静止镜头绘制 / 传屏均值 | 约 10.7～15.4ms / 5.0～8.9ms |
| 滚动镜头绘制 / 传屏均值 | 约 28～29ms / 20～21ms |

FPS 统计成功完成的实际传屏，含循环调度和其他任务开销。均值仅纳入常规约一秒窗口，排除不足一秒及退出后累计空闲时间的强制汇总；原始窗口全部保留在测量文件中。

此前同设备保存优化后的采样平均为 16.86 FPS，静止镜头仍约每 100ms 才刷新一次。本次随机路线、地图资源及游戏状态与此前不同，此对比不是固定路线基准。地图切换仍观察到约 350ms 的传屏间隔、370ms 的帧开始间隔，尚未消除整体行走中的所有停顿。本轮没有通过相机观察设备屏幕，残影验证来自真实渲染器的逐像素测试；未在 V1 设备或 release 固件上测帧率。

两轮均正常回房并成功保存，首次刷入前为 91 步、2883 金币、11 瓶药水，最终为 207 步、3054 金币、13 瓶药水，HP 为 60/27；这是实机正常游戏产生的状态变化。最终重启再次核对内存与存档一致，设备保留本次 V2 调试固件并停留房间。

采集文件位于 `tools/out/explore-motion-20261014/`：`measurement.json` 包含全部窗口和汇总，`measurement.log` 为筛选日志，`flashed-images.json` 记录刷入文件哈希，构建和测试日志同目录。`config-before.bin` 含私人配置，原始启动日志也可能包含网络配置，勿公开。
