## 1. 目标与行为边界

用户希望精灵在已搭建的市集中自然走动，使用已铺设的道路，能够回头、停留、进出，不呈现固定顺序、整齐往返的巡逻效果。

已明确的要求：

- NPC 使用宝可梦精灵资源。
- 常驻精灵能够在指定区域内活动。
- 随机访客从用户选定的候选中抽取，排除神兽；现有候选也排除幻兽。
- “一大一小”指同一进化链的进化型与最初幼体，不通过缩放同一张图制造大小。
- 访客隔一段时间从出入口进入，活动后离开。
- 当前市集入口在底部，应使用地图记录的入口，不从任意边缘空地出生。
- 道路允许双向通行，回头或再次经过同一路段属于正常活动。

本文建议将精灵分成“常驻摊位精灵”和“逛市集的结伴访客”。角色分工和下文的参数是实现建议；不应直接覆盖用户现有配置。玩家自身的探索路线与 NPC 活动独立，本任务不要求改变玩家控制、探索段数、遭遇或奖励规则。

## 4. 建议的自然活动规则

### 4.1 常驻摊位精灵

继续使用随机散步：从自身可达范围选择目标，走到后停留，再选择下一个目标。摊位之间无需按固定次序移动。

建议参数：

- 每格移动 500～800ms；保留当前 600ms 作为初始值即可。
- 到目标后停留 3～8 秒，各只精灵独立抽取，避免同时起步。
- 同时存在其他选择时，降低刚离开位置与最近访问位置的权重；允许为了避障或走出支路而回头。
- 区域只有两格时仍允许运行，编辑器提示活动范围较小；不自动扩圈到水面、其他摊位或整张地图。

其中“减少近期重复目标”的权重属于待实现行为，当前 `WANDER` 是从可达候选中随机抽取。

### 4.2 随机结伴访客

建议行为过程：

```text
等待下一组 → 抽取同链组合 → 从底部入口走入
    → 选择一个可达停留位置 → 沿道路过去 → 随机停留
    → 可选择另一个位置继续逛，或结束本次访问
    → 回到入口 → 完整走出画面 → 开始下一次间隔
```

不要把“遍历全部道路”设为每次访问必须完成的任务。每次访问可随机选择少量目的地，顺序、停留时间和经过的支路可不同；允许有的访客只看一个摊位就离开。

为延续现有配置，建议将 `stayMinMs/stayMaxMs` 继续解释为到达首个停留位置后的访问预算，包含闲逛和停留，不包含最初入场与最终离场。每处短暂停留可先采用 3～8 秒；新增参数与旧数据的兼容规则需在实现时显式编码，不能静默改变所有旧工程。

结伴关系建议：移动时一前一后，停留时优先选择相邻两处空位。幼体跟随同伴，不独立随机跑遍地图；同伴被挡时等待或重新选择附近可达位置。保留完整原精灵比例与动画。

入口、窄路和停留点共享动态预约。对向相遇时等待、换目标或退让，不允许穿过对方、瞬移、重叠；停留点不足则推迟本组入场。退出时沿可达道路回入口，不要求机械倒放整段游览轨迹。

### 4.3 道路与停留区域

访客主要沿已铺道路移动，摊位停留区可以是紧邻道路的少量空地。需要建立“路网节点 → 停留位置”的合法连接，检查整段连接是否穿过物件占地或水面。

“地图可通行”不等于“访客可以随意走到所有草地”。建议导出道路导航与停留区两个集合；常驻精灵仍受自己的活动区域限制。现有来源判断、最终可见物件占地与桥面语义应统一复用。

## 5. 固件接入设计建议

### 5.2 先解决坐标与路线表示

当前存在两种不同表示，不能直接混用：

| 表示 | 例子 | 逻辑世界坐标 |
| --- | --- | --- |
| NPC 地面格中心 | 格子 `(x, y)` | `((x + 0.5) × 26, (y + 0.5) × 26)` |
| 新路网中线节点 | 节点 `(x, y)` | `(x × 26, y × 26)` |

路网还含地图边界节点，例如底边 `y=12`。这是合法的路网位置，不是可直接索引到 192 格数组的地面格；不能将其打包成 `y*16+x` 后交给现有 NPC 网格模拟。

建议为道路导航增加独立的有界节点／边表示，显式转换到世界坐标，并为摊位格中心添加连接点。坐标可采用半格整数单位保存，避免丢失格心与中线的半格差。路网导航与地面格预约需要适配层，覆盖节点、边与连接段的冲突，尤其是同一条边上的对向移动。

经典 `ExploreMapGenerator::Path` 最多 48 点，当前道路往返路线为 53 点。不要截断、去重或扩大某个数组后就宣称兼容。NPC 应使用路网导航；若玩家也要采用这类路线，需另行设计玩家路线适配并检查所有消费端。

### 5.3 数据与导出

建议交付的数据内容包括：

- 最终三层地图及资源依赖、素材来源校验值。
- 路网节点、无向边、入口连接、拓扑版本与有效性检查。
- 停留区域、可用停留位置及其到路网的连接。
- 常驻精灵物种、出生位置、活动范围、速度和等待参数。
- 随机访客候选链、间隔、访问预算、每区并发限制及运行种子规则。

现有经典导出包已能生成 `AuthoredMap.h`、`activity.json`（version 2）、`AuthoredNpcs.h`、`AuthoredPopulations.h`、精灵来源表与原 `.smonsp` 包；包含 `roadNetwork` 路线的当前工程会在到达这些输出前被拒绝。需要扩展编译器与场景加载入口，不能仅复制 PNG 或 JSON 就认为完成接入。

新增导航数据应带明确版本；旧版缺少路网时保持已有区域散步／停留规则，新版固件才能消费新增行为。无效索引、不可达停留点或过期道路来源应阻止导出，错误信息指出具体区域或连接。

### 5.4 运行与资源

- 复用固定 100ms 模拟步长与绘制插值。菜单、战斗或暂停场景冻结活动时间，恢复后继续原状态，不集中补算离开期间的访客。
- 入图初始化一次模拟与随机数；暂停不重置，运行种子改变后可以产生不同的访问结果，测试时可固定种子复现。
- 当前核心上限为固定 NPC 与来访预留合计 16 只，每个来访区域预留 2 只，最多 8 个来访区域。本地图需求为 5 只；这些是配置上限，设备容量仍需测量。
- 固定 NPC 的 `AuthoredNpcPopulation::Pose.speciesId` 为 0，需要按常驻配置映射物种；随机访客按 `speciesId` 选择资源，`visible=false` 时不绘制。
- 使用原帧尺寸、方向与脚底锚点，NPC 脚底参与深度排序和物件遮挡。道路中线、脚底与相机采用同一世界坐标，不能重复增加半格偏移。
- 资源按场景预载或复用现有缓存，不在每帧解包或从存储读取。候选池素材包是否全部驻留需按目标设备的内存实测决定。
- 瞬时位置、等待计时和随机数先作为场景运行状态。持久化并非本次已确定需求；后续若需要跨重启恢复，应通过现有存档服务做版本化设计。

## 6. 建议实施顺序

1. **确认地图基线。** 重新核对素材记录，适当扩展常驻区域，检查常驻与访客停留位置竞争，保存一份待接入工程；本次快照仅作交接基线。
2. **建立路网导出与共享导航。** 支持环路、支路、双向通行、地图边界与停留区连接；分离 NPC 导航与经典玩家路线限制。
3. **接入市集场景和常驻精灵。** 明确进入市集、离开市集的条件，先验证三只常驻精灵、锚点、遮挡、暂停和资源预算。市集出现于哪个地区／时段、哪些设备先接入，尚未指定，不在本文中擅自决定。
4. **增加自然结伴访问。** 在同一共享核心中实现随机目的地、短暂停留、同伴跟随、再访问或离开，以及通道预约和受阻重选。
5. **统一编辑器预览与固件。** 相同数据、种子和 tick 下比较状态轨迹；更新数据版本、导出说明和回归测试。
6. **目标设备验收。** 按实际选择的设备完成构建、帧图检查与容量测量，再制作待刷包。修改共享规则时按仓库要求完成相关目标构建；本次文档不执行构建或刷写。

## 7. 验收条件

- 当前市集从底部入口可到达所有启用停留点；到不了的位置在导出前被指出。
- 常驻精灵留在所选区域，随机移动并有停留；不会全体同时起步。两格区域可运行，但明确提示观感局限。
- 来访组合只来自所选候选池，进化型与幼体属于同一进化链，不出现被排除物种。
- 连续多次访问的目标或停留安排可变化，没有“必须完整遍历道路再折返”的强制规则；固定种子下可复现。
- 允许回头、再次经过节点、绕环路及从同一入口进出，支路不会造成循环卡死。
- 同伴保持联系；道路对向相遇、停留区满员、入口堵塞时能够等待或重选，不穿模、不瞬移、不叠在同一位置。
- 动态受阻后能恢复；不可恢复时停止本次新访客入场并保留已在场角色的有效位置，不能用越界或穿障碍强行完成。
- 精灵从画外完整走入、完整离开后隐藏；高个精灵不会在边缘突然截断出现或消失。
- 相同数据／种子／tick 的编辑器与 C++ host 模拟结果一致；暂停恢复不重抽、不跳时。
- 设备实际画面中，脚底对路、树冠与摊棚遮挡正确，性能和资源驻留满足目标设备预算；构建通过与实机通过分别记录。
- 原有地图、玩家探索与存档行为保持预期；新增入口和地图资源有明确选择条件。
