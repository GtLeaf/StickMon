# 长草园 P1 生成优化（2026-11-01）

此次仅优化共享地图生成器的树木候选计算。谷仓、StickS3 和 AMOLED 均使用该代码。
地图外观、路线、随机分布、随机数调用顺序、资源和算法版本保持不变。

## 实现

- 每次选树只评分一次，将分数放入固定大小的栈上数组；按原行优先顺序统计、抽选。
- 预计算到已有树木的曼哈顿距离，保留原来的上限 6。两次方向遍历替代每个候选
  对全图树格的重复扫描。
- 预计算已有可种草空间。三行树体只会影响同列的四行草根位置，因此逐候选仅扣除
  这部分原本有效的位置，不再复制树掩码并重算全图空间。
- 新增临时分数数组 384 B、距离数组 192 B，不分配堆内存、不增加常驻地图缓存。
  具体调用栈峰值仍由目标编译器和上层调用决定。

P2 补草／道路检查和 P3 动画更新未在本批实施。本优化针对进图／切图时的生成停顿，
不能据此宣称走路帧率提高。

## 验证

- 1,024 个固定种子 × 四入口，共 4,096 张地图，优化前后完整图层、入口、出口、
  分岔、路径及地图指纹一致；三轮交替执行均一致。
- 9,360 组候选选择与穷举参考一致，包括随机数后续状态；49,920 个距离值与穷举
  参考一致，覆盖空／满树掩码、底边树木、道路占满、稀疏／密集占位、三种宽度、
  顶边限制、相邻许可和三种种草目标。ASan／UBSan 通过。
- 地图回归覆盖现有 Python/C++ 指纹、长草配对、树木完整性、出口拓扑和双格道路
  防短接。谷仓 build-native、StickS3 release、AMOLED V1 lite 构建通过。

## 桌面测量

相同 C++ `-O2` 配置，冻结修改前生成器与新版交替执行三轮，每轮 4,096 张地图。
计时仅包含 `generate()`，不含输出、资源读取或渲染；测量期间本任务未并行构建。
下表取三轮各指标的中位数，详细原始记录保留每轮最大值，不能视为严格最坏耗时保证。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 单图耗时中位数 | 364.40 μs | 99.40 μs |
| 单图耗时 P95 | 597.79 μs | 168.88 μs |
| 4,096 张总耗时 | 1,570.34 ms | 435.88 ms |

总耗时下降 **72.24%**。这是桌面 CPU 的生成测试，不能直接换算为 ESP32 耗时、
实机收益比例或 FPS；谷仓实测结果见下节。

## 谷仓实机测量

2026-11-01，在谷仓 ESP32-S3（240MHz、32MB Flash、8MB PSRAM）上完成对照。
同一 Debug／trace 测速固件包含原版与优化版评分实现，交替先后顺序，预热后测量
256 个固定种子 × 四入口 × 三轮，共 3,072 对；每轮有 1,024 张不同地图。
计时仅覆盖 `generate()`，不含打印、渲染和传屏；测速在游戏会话启动前执行。

| 单图耗时 P95 | 248.17 ms | 49.10 ms | 80.22% |

| 样本内最大耗时 | 401.64 ms | 101.24 ms | — |

任务剩余栈低水位为 14,252 B，未见断言、崩溃或看门狗异常。

收益针对长草园进图／切图中的**地图生成阶段**，并非整个切图耗时或行走 FPS。
