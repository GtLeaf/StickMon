# 谷仓右侧触摸渐进补偿

2026-11-02：根据四轮九点诊断，尝试修正右侧单击落点偏差。无需再次采点；
这是内置的实验性补偿，不代表实机校准已经验收。

## 映射范围

只改谷仓平台输入，不移动界面或放大按钮。传感器方向仍为 `x=rawY`、
`y=359-rawX`，随后才进行补偿。

| 锚点 | 四轮末次坐标中位数 | 目标 | 修正量 |
| --- | --- | --- | --- |
| 右上 | (344.5, 113) | (309, 126) | (-35.5, +13) |
| 右下 | (335.5, 248) | (309, 234) | (-26.5, -14) |

水平方向从 x=180 到 320 使用 smoothstep 增加权重；纵向从 y=56 到 113
逐渐进入补偿，从 y=248 到 309 逐渐退出。两个锚点间平滑插值修正量。
x≤180、y≤56、y≥309 的坐标完全不变，顶部导航和下缘不受该补偿影响。
各过渡边界的位置与一阶导数连续。

DOWN/MOVE 使用相同映射，UP 继续使用末次有效位置。原 I2C 失败取消、
非法坐标拒绝、等待松手及接触状态语义保持。补偿向内收缩右侧可达坐标范围，
不能把它视为最外缘所有位置的精确逆映射；不把越界样本强行压成边缘点击。

## 与已有校准的关系

`STICKMON_SDGOODS_RIGHT_TOUCH_COMPENSATION` 默认 ON，只在没有有效保存的
仿射校准记录时启用。读取记录不修改 NVS。启动日志应显示：

```text
[TouchCorrection] right_progressive=1 saved_affine=0
```

有效的已保存校准优先，此时渐进补偿关闭，避免重复修正。正式校准采点时的
bypass 同时绕过两种补偿，成功保存后仅使用保存的仿射映射。
已有“恢复默认”保存单位映射的行为保持，因此明确保存的单位映射也会关闭
这次实验补偿，并在重启后继续生效。保存失败保留先前映射和补偿模式。

需要从构建关闭时：

```bash
bash firmware/sdgoods/build.sh -B build-debug \
  -D STICKMON_ENABLE_DEBUG_FEATURES=ON \
  -D STICKMON_ENABLE_TRACE_LOGS=ON \
  -D STICKMON_SDGOODS_RIGHT_TOUCH_COMPENSATION=OFF
```

## 验证与限制

新增检查包含四轮记录的右上/右下坐标回放、全屏坐标边界、左侧/顶部/下缘
不变、连续性、局部映射不折返，以及实际传感器方向转换后的 DOWN/MOVE/UP、
原始采样旁路、失败取消和已保存仿射路径。校准记录存在性区分包含单位映射、
坏记录和正常记录，不改记录格式或游戏存档。

八个既有右侧样本的浮点回放平均误差 31.84→7.66px，最大残差20.45px。
这些样本也用于确定锚点，不是独立实机验证；尤其第二轮右上样本会过度补偿。
四轮人工点击包含指腹和瞄准差异，固定映射无法消除随机变化。

证据、修改前快照及构建日志位于
`.stick-local/artifacts/sdgoods-touch-right-compensation-20261102/`。
本批不刷机，不写实机校准或游戏存档，保留用户音量0。

## 用户反馈

2026-11-02，用户实机确认“更准了，可以先保持这样”。当前补偿参数暂时保留，
无需重新采点。对应交付包为
`.stick-local/firmware/sdgoods/right-touch-compensation-debug-20261102/`。
此反馈确认右侧点击的实际改善，不代表全屏误差已完成定量验收。

同日后续用户反馈“还是不行，3，4，点位还是很偏”，撤回前述暂时接受结论。
当前方案未解决右上／右下精度问题，不能作为已通过实机验收。尚缺补偿后
偏移方向／坐标以及运行时补偿开关的核验，暂不据此增加固定修正量。
