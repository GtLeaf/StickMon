# 多设备 UI 隔离规范

更新：2026-10-26。十三批隔离实现已收口。本页合并当前需求与设计，删除旧“剩余批次”排期；
原分批验收见 [acceptance.md](acceptance.md)，后续改版见[多设备 UI 隔离说明](../../doc/多设备UI隔离.md)。

## 构建家族

| 目标 | 家族与表面 |
| --- | --- |
| StickS3 | src/ui/stick，240×135，A/B／IMU |
| OSTB | src/ui/compact_touch，296×240，A/B 与触摸 |
| SDGOODS | src/ui/round_touch 专用房间／孵化／主菜单及表面门面，子页复用 compact_touch；360×360 物理帧与中央 240×240 页面 |
| AMOLED V1/V2 | 独立竖屏应用，V2 复用 V1 的 app／ui 权威源清单，不编译横屏场景 |

家族由 UiProfile／构建源清单显式选择，页面尺寸由 PageProfile 给出。新增设备可复用家族或增加
独立家族；不得按画布宽高猜测设备，不能在共享场景和玩法服务中扩散板型号分支。

## 行为与边界要求

1. 当构建 StickS3 时，应仅编译 Stick 孵化／菜单公共叠层／Debug／成长／无线通讯／洗澡／探索／战斗／主房间／主菜单／商店／背包／队伍／状态／技能／房间菜单／食物选择／电脑入口／通讯录／设置界面，保持当前 240×135 布局与 A/B 操作。
2. 当构建 OSTB 时，应仅编译 compact_touch 孵化／菜单公共叠层／Debug／成长／无线通讯／洗澡／探索／战斗／主房间／主菜单／商店／背包／队伍／状态／技能／房间菜单／食物选择／电脑入口／通讯录／设置界面，保持当前网格、详情、确认与滑动操作。
3. 当不同界面执行同一购买、出售或道具操作时，应复用同一功能流程和玩法规则，得到相同游戏状态；拖动、取消、重复松手不得交易。
4. 当切换 UI 家族时，不得改变存档格式、物品目录、解锁条件、战斗背包结果或资源格式。
5. 当新增设备时，应能选择已有 UI 家族与设备参数；独立交互可增加新家族，不把硬件型号判断散入共享功能。

6. 当操作队伍和技能时，应复用共享查询／语义流程，并经原 GameEngine 服务完成首位、离队、遗忘及回忆；访客限制、探索上下文、永久队序和心之鳞片消耗不变。
7. 当查看状态页时，应保留原五页、仓库和蛋页；Stick 倾斜滚动与 OSTB 跟手切页／回弹分别由各自家族管理，正文全宽和顶部圆角间距不变。
8. 当静止、取消触摸、离开页面或销毁页面时，应保持刷新需求和动画缓冲释放契约；Stick 不携带 OSTB 的触摸／切页缓存状态。

9. 当操作房间菜单或食物选择页时，应将两家族的排布、输入、滚动和文字动画分别放到选中的界面实现；房间顶部安全区与食物页现有样式保持不变。
10. 当选择有库存的食物时，应通过原 GameEngine 接口只改变选项并保留保存标记；选择空库存、取消或拖动不得消耗食物或改变选项。洗澡仍受原孵化／队伍条件限制并进入原场景。
11. 当显示房间食物数量时，应保持原家族语义：Stick 显示 255 封顶的总量，compact_touch 显示完整总量；无效选项按原查询归一到普通粮，查询不得修改存档。

12. 当进入电脑或通讯录时，应委托所选家族的界面，保持电脑原列表／卡片、通讯录列表及操作／邀请／删除弹窗和滚动行为；Stick 保留原导航，compact_touch 仅保留安全顶栏返回，无底部导航或返回条目；电脑／通讯录的范围不包含无线通讯场景，后者见 30–32。
13. 当查看联系人或操作邀请、删除时，应复用 ContactRoster 等原查询规则，实际变更继续经 GameEngine；队伍中的实时状态映射、孵化来源保护、来访／每日锁定／队伍已满限制、确认默认值、提示时长、加入到达演出与保存标记保持不变。
14. 当取消确认、拖动、重复松手、离开页面或切换输入时，不得误邀请或删除；静止列表和弹窗完成滚动后应停止刷新，返回应保持原页面层级。

15. 当进入设置、帮助或重置确认时，应将两家族的绘制、列表／滑杆输入和临时状态放到各自界面，保留原列表顺序、由 PageProfile 提供的安全触屏顶栏（OSTB 为 48px）、帮助文案与翻页、重置默认取消和提示样式。
16. 当修改亮度、音量、速度和省电选项时，应经共用应用回调调用原硬件／GameEngine 接口并保留保存标记；Stick 音量入页按 10% 取整，compact_touch 保留连续音量，亮度档位与滑杆范围、试听和静音停止行为不变。
17. 当拖动、取消或重复松手时，应保持原滑杆轴向判定与列表滚动行为，不得误重置；重播教程、返回和重置成功同步切场景后不得继续访问旧界面，通知到期和列表静止后应停止刷新。重置失败仍显示原 1500ms 提示并保留游戏。

18. 当显示主菜单时，应按家族委托绘制与输入：Stick 保留图标列表、选中项动画、电量显示与 30 秒检查，compact_touch 保留自适应图标网格、按压、拖动与停绘；release 八项、debug 九项及标签／图标顺序继续复用 AppSceneFlow。
19. 当进入或离开主菜单、从子页返回时，应保留原选中项记忆、从 home 入页归零、循环选择与教程完成条件；探索中的队伍／背包返回语义、导航栈和战斗背包结果不变。
20. 当激活主菜单入口时，应继续由原应用协调执行导航与探索限制（未孵化／无队伍、访客、濒死），保留 1100ms 提示；取消、拖动和重复松手不得误进入页面，同步切场景后不得访问旧 UI。Debug 子页也已委托家族 DebugUi，release 不包含该界面实例。

21. 当显示主房间时，应由按家族选择的 HomeUi 管理相机、HUD、提示与输入，共享只读 HomeFrame 和房间表现内容；保持 Stick 240×135 镜头及 OSTB 240×161 原比例居中、影子脚锚、昼夜、图层与触摸命中顺序。
22. 当摸头、添粮、进入菜单或处理过场和成长弹窗时，应继续由 MainScene 协调原游戏服务、教程、导航和保存；寻路、碰撞、角色活动、访客及存档坐标不得复制进 UI 或改变。core/ProgressionUi 保留应用适配器，绘制和视觉／输入状态委托家族 ProgressionUi。
23. 当拖动、取消、锁屏或切场景时，应保留原轻点取消与过场拦截，销毁后不得继续访问旧界面；主房间保持原 66ms 调度及通知在原正常更新路径到期的行为。Debug 组合保存、饥饿插值和相机临时状态归 UI，保存动作仍由应用执行。

24. 当显示探索区域、路线及横屏战斗时，应委托所选家族 ExploreUi，通过只读区域／路线与战斗快照复用相同内容绘制；家族显式提供布局参数，不按尺寸猜测家族。compact_touch 已接入地区列表、路线、战斗和菜单触摸；几何及取消规则由家族持有。
25. 当选择区域、侧菜单、战斗命令或确认选项时，UI 管理游标、缓动、蛇行展示朝向与选中状态，以语义动作交给 ExploreScene；原按键优先级、子视图、80ms 延后解码、轮播、遮挡顺序和刷新调度保持不变。路线、碰撞、遭遇、战斗规则、日志／成长／投食／换人时序、保存和资源预加载继续共用。
26. 当出发或调试战斗返回同步替换场景时，不得继续访问已销毁对象；以冻结原源码的两家族 release/debug 画面、真实流程与内存检查核对。AMOLED 原竖屏探索和战斗不变。

27. 当显示横屏洗澡时，应委托所选家族 ShowerUi，以只读帧共用原画面，界面持有选择、工具、IMU 平滑、水滴、浮字及反应等临时状态；保持八个模式与各家族布局；Stick 保留 IMU／无 IMU 按住 A，compact_touch 使用固定按钮与精灵区域按住拖动。
28. 当上皂、擦洗、冲洗和退出时，应保留 Stick IMU／无 IMU 按住 A 与 compact_touch 触摸拖动各自的时序；阶段、泡沫规则、一次性奖励、访客限制、库存立即保存及 1／2／3 心恢复继续由原共享服务与场景协调，不改变存档 schema。
29. 当洗澡未完成提示到期并同步替换场景时，应立即结束旧对象更新；以独立旧源码像素基线、两家族 release/debug 的真实流程、停绘／唤醒及内存检查验证。AMOLED 洗澡保持原独立控制器。


30. 当进入无线通讯时，应委托所选家族 SocialUi，保留菜单／房间列表／请求确认／错误和等待画面及 A/B 语义；compact_touch 已接入触摸选择与确认，取消和弹窗不得穿透。
31. 当创建、搜索、加入、接受／拒绝或结束拜访时，应经 SocialHost 回调调用原 VisitSessionService；无线链路、协议、重试／超时、存档及访客规则不变。进出场景仍由 SocialScene 协调链路生命周期和 ACTIVE 返回主房间。
32. 当会话状态、房间数或等待点动画改变时，应保留原重绘和 66／200ms 唤醒；静态页停绘。以冻结原源码的四配置画面、真实协议操作和同步销毁路径验证。

33. Debug 子页应由选定家族持有分类、光标、滚动、数字输入及绘制；release 不得包含 Debug UI 状态或代码。保持原分类条目、A/B、长按、弹窗、通知与战斗返回。
34. Debug 游戏变更、导航、保存及成长队列仍经原应用接口执行；界面只提交语义动作。保留空队伍、满级、无联系人、忙碌、倒下等拦截与通知时长。
35. 共用升级、进化／取消、学招式／替换提示应通过家族 UI 提供；绘制不得直接读取引擎。保留原像素、动画／叫声时序、确认默认取消、替换失败重试及资源生命周期，成长队列与规则不变。
36. 修改时应以修改前工作树独立冻结源码校验两家族 release/debug 像素与真实操作，并完成原回归、内存检查、源隔离及四目标构建；AMOLED 独立竖屏控制器保持原边界；构建与实机验收分别记录。

隔离本身不改变玩法或存档。后续有意界面变化应使用经审查的独立基线。十一组菜单、主房间、探索／战斗、洗澡、无线通讯、Debug 子页、共用成长表现、孵化页及菜单公共叠层纳入隔离；应用外层导航／资源提示／淡入淡出及通用触摸策略也已纳入隔离；通用表现工具保持共用，AMOLED 现有竖屏应用按原设计继续独立。横屏隔离代码收口不代表实机验收或全仓库测试全部通过。

37. 孵化页应由所选 HatchUi 管理相机、蛋、倒计时、提示、视觉观察及输入命中，以只读帧复用原 HatchService；保留资源缺失回退、昼夜、晃动、700ms 提示、物理 A 擦拭／其他键轻拍与 A 长按菜单；触摸家族沿用各自的轻拍／擦拭／菜单语义。
38. 孵化 elapsed、互动计数、运行时恢复、15 秒保存／失败重试、离页保存和完成选种继续由 HatchScene 与原引擎接口执行；保持原时序、游戏速度调度与同步销毁后立即返回，不改 schema。
39. MenuScene 公共底色、通知样式及教程绘制应由所选 MenuOverlayUi 承担；应用保留文本、通知期限、页面路由及教程进度。保留页面通知可见性、叠层顺序、各家族教程显示策略（谷仓保留触摸新手引导）与探索上下文限制。
40. 修改时应以修改前工作树独立生成四配置像素及真实孵化／菜单旅程，完成内存、既有像素／服务／存档、源选择和五配置构建检查；核心外层导航已在第十三批隔离；AMOLED 独立应用继续保留，不宣称全仓库 UI 都使用同一套家族。

41. 应用外层底部虚拟导航、资源缺失提示及场景淡入淡出应由选定 ApplicationUi 绘制；保持原像素、导航／资源警告／淡出叠层顺序、缺失原因优先级和暗化公式，不改变资源加载及场景切换时序。
42. Scene 通用触摸应通过所选家族 SceneInput 策略获得内容／导航命中与按键语义，应用基类只管理轻点生命周期与分发；保持原 32px 导航命中、边界、取消／拖动／超时／重复松手及同步销毁后的立即返回，不新增触摸入口。
43. 修改时应独立冻结工作树验证两家族 release/debug 的外层像素、真实输入／淡出切场景、锁屏／资源警告输入拦截及内存安全，完成既有回归和五配置构建／源审计；AMOLED 仍独立，通用绘制／资源工具无需迁为家族业务，实机验收另行安排。


## 当前所有权

| 层 | 负责内容 | 约束 |
| --- | --- | --- |
| src/game | 物品效果、价格、库存、战斗、成长、存档内游戏状态规则 | 无 UI、硬件 SDK 依赖 |
| src/core/features | Shop／Bag／Team／Moves／Room／Contacts 的只读目录、能力与语义流程 | 实际保存、切场景和硬件副作用经应用回调 |
| GameEngine／scenes | 游戏协调、导航栈、存档、通知期限、资源预载、协议与场景生命周期 | 只向 UI 传只读帧，消费语义动作，不持有家族布局或触摸缓存 |
| src/ui/stick、compact_touch、round_touch | 家族布局、命中、滚动、相机／视觉状态与按键／触摸解释 | 不直接引用 GameEngine，不复制 GameState／地图，不在绘制中变更玩法 |
| src/ui/common | 只读帧、Host 接口、可共用内容绘制与表现工具 | 不强行统一家族几何、交互差异或平台服务 |
| SceneSurface／ApplicationUi／SceneInput | 场景页面表面、外层导航／资源提示／淡出和通用输入策略 | 核心仍保留输入拦截、时钟、帧提交与场景替换 |

可能同步销毁场景的回调之前先清理手势与临时状态，回调后立即返回。通知文本复制到拥有者，
不保留栈字符串。状态跟手页临时图、视觉时钟与相机不进入存档，取消／离页必须释放缓存。
静态页停止绘制，按各自 RenderDemand 只唤醒真实动画、滚动或通知截止时间。

## 验证规则

- 结构迁移使用修改前生产源码独立生成像素／行为基线，覆盖所选家族 release/debug、真实导航及同步销毁。
- ASan／UBSan、源清单／头文件依赖／家族互斥、release Debug 门控、存档兼容和受影响构建应核对。
- 有意改版另建经审查的基线；既存失败按修改前后复现记录，不能重录旧 fixture 掩盖差异。
- 实机显示、触摸、音频、性能和跨设备无线独立验收；历史主机检查不代表全部硬件已通过。
