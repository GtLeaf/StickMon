# 谷仓独立资源存储需求

范围：用户已确认同时实施三批；仅谷仓启用，微雪与 StickS3 保持现有分区。

1. 当构建谷仓固件时，应输出物理 32 MiB Flash 上地址范围不超过 16 MiB 的自有分区表（双 3 MiB 应用、单 9 MiB 资源区）；显式完整布局可选 32 MiB／24 MiB 资源与独立 LittleFS 镜像；应用不再链接整包图片、音频与内容表。原存档、设置、触摸校准的 NVS 地址和命名空间保持。
2. 当资源包增加固件已支持规则的精灵或调整现有地图时，应从版本化目录读取属性、招式、学习表、动画、尺寸、地图、NPC、遭遇、掉落和商品配置。稳定 ID 不重排；新规则和超出 ABI 容量的变更仍需要固件。
3. 两个应用槽共享只读资源，当前只开放 USB ROM 完整安装，禁止运行中覆盖共享资源。试运行验证前不写游戏存档；bootloader 只回退应用，不承诺资源回退。后续运行中升级需另行设计。
4. 当布局、ABI、签名、文件摘要、表结构或存档不兼容时，应拒绝激活或进入最小恢复页；禁止混搭资源、自动格式化和清空存档。
5. 当首次通过 USB 安装时，应核对芯片、32 MiB Flash、明确 MAC 和完整旧分区，只写计划中的区域，不自动备份、不整片擦除。首次布局迁移中断可经 USB 重新安装，不能冒充后续更新的掉电安全事务。
6. 验收应覆盖静态／外置数据等价、真实圆屏流程、错误输入和事务故障注入、相关机型构建及可执行的设备启动／切槽测试；实机缺项必须明确记录。

7. 默认上传用连续镜像应固定为 16 MiB；显式完整布局输出 32 MiB，并校验签名、各段地址／内容与空隙。连续首装镜像写入会清除 NVS；现有设备定点安装应保留原 NVS，不把两种方式混用。

8. 发布前应从实际生成的文件系统镜像运行固件同一份启动内容校验；有效目录必须先通过，表间未知引用即使有一致摘要也不得签名发布。
