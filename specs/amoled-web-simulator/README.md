# 微雪 V2 网页模拟器规范

更新：2026-10-26。本地实现已交付，需求、设计和任务合为一页；使用方法见[运行说明](../../doc/微雪V2-网页模拟器.md)。

## 行为要求

1. 当用户选择 StickMon × 微雪 V2 并打开试玩时，站点应懒加载真实 AMOLED 应用的 368×448 网页构建。
2. 当用户点击、拖动或取消触摸时，游戏应收到正确输入；取消手势不得变成一次点击。
3. 当用户重启或收起重开时，应恢复最近成功保存的进度；保存失败应显示提示。微雪与 Stick 存档应隔离，损坏及未来版本存档不得被默认状态覆盖。
4. 当页面隐藏或失焦时，试玩应暂停时间和声音；正常关闭面板时应先请求保存，再释放实例。
5. 当页面宽度为 320px 或 375px 时，游戏应等比显示，面板不得裁切，页面不得横向溢出。
6. 当产物缺失或目录非法时，后台应拒绝启用，公开 API 不应报告可用；新发布应保留旧资源供进行中的下载完成。
7. 当用户使用原 Stick 试玩时，原入口与存档保持兼容。

边界：仅微雪 V2 游戏试玩，不模拟 V1、真实 OTA、远程聊天和无线硬件。不发布线上环境。

## 设计与所有权

- `WebPlatform` 已在当前源码树中，支持目标尺寸、存档前缀和受控时钟。目标构建使用明确源码清单、AMOLED UI 公共清单及隔离的对象缓存。
- `main_amoled.cpp` 绑定真实 AmoledApp/Canvas565；纯 TouchEvent 头与硬件驱动分离。浏览器管理帧循环，通过导出函数传入逻辑时间和触摸，复用脏区域传屏。
- 页面使用 Pointer Events 和指针捕获。浏览器取消触摸调用独立 cancelTouch，不进入 UP 的业务动作路径。
- localStorage 使用设备前缀；Web Locks 保障同一设备目标的单写实例；所有写入失败向 SaveManager 返回失败。快照格式共用现有 schema 3 / save v5。
- iframe 消息均校验 origin/source。支持 ready、resize、input、close/closed、pause/resume，关闭有界等待确认，保存失败给出提示。
- 刷机站复用组合与模拟器表，后端校验产物完整性。启动补登记已有 V2 组合；管理端支持新增登记，保留管理员的停用选择。
- 发布器在临时目录完成全目标验证，先复制哈希资源、最后切换入口。自动发布直接构建同一提交的两个目标，避免再依赖长驻 Web 分支合并。
