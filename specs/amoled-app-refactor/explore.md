# 探索会话批次

日期：2026-10-18。用户已确认执行上一轮建议。本批只提取 ExploreSession；Presenter 和 HomeFlow 留待后续。

## 范围与验收

- 当相同初始状态、随机输入和步进命令重放时，地图指纹、路径、拾取、遭遇物种/等级及随机调用顺序应与拆分前一致。
- 当一次移动完成时，步数、十步恢复、冷却和道具计步只能结算一次；冰面、碎冰下落、跨图和 Boss 优先级应保留。
- 当拾取或返程重复触发时，不得重复发奖；拾取、Boss 保底、出发、成长交接、战斗关闭及返程保存边界应保留。
- 当暂停后恢复时，移动、退场和碎冰等待应继续剩余时长；玩家点击行走与自动探索应保持独立。
- Session 只持有会话状态，显式接收 GameState 并复用 src/game 规则；无 App 回指、硬件、存储或绘制缓存依赖。App 消费固定类型效果，state() 只读。
- 绘制、插值、相机、生态显示、素材和音频预热由 App 保留。资源包、分区和存档 schema 不变。

## 实施结果

- 新增 `app/ExploreSession.{h,cpp}`，拥有地图、活跃池、路线索引/步数、Boss/遭遇/拾取、冰面与道具、暂停和返程结算状态。复用现有 `ExploreMapGenerator`、`ExploreEncounterRules`、`ExploreBossPity`、`ExploreSpecial`、`ExploreRunRules`、`MonsterFactory` 和背包/亲密度规则。
- App 通过 `takeEffects()` 消费保存、地图表现重置、战斗准备、下一步/退场和返程请求。地图只有一份，模型和生态持有该成员的只读引用；不复制 GameState，不引入 AppContext 或动态事件总线。
- App 继续拥有坐标插值、跟随者表现、相机、帧时钟、生态/草丛与脏区、资源预热和房间门口/淡变流程。`exploreSessionActive` 仍表示从出门到入门完成的整段生命周期，用于暂停居家恢复，与路线的 moving/paused 标志不同。
- 删除只供测试调用的 App 玩法转发入口，测试改为操作会话并显式消费效果。探索步进的源码位置断言替换为真实 App/Session 行为测试；音乐与渲染集成检查适配新边界。
- `AmoledApp.cpp`：13,036 → 12,249 行，减少 787 行；头文件 858 → 813 行。Session cpp 939 行。行数仅说明迁移规模，不代表性能提升。

## 明确的行为修正

1. 总菜单的返回房间入口，在探索期间改走现有返程淡变、结算和保存，避免直接回房绕过探索收尾。
2. 暂停/恢复同时顺延移动、退场、碎冰等待和地图动画时钟；战斗与成长交接沿用同一个暂停锚点，关闭战斗后在保存/缓存操作完成时取新时钟，避免下一次行走追赶整段隐藏时间。
3. 拾取和返程结算、完成步和退场、待处理战斗请求具有重复调用保护。返程保存失败仍由已有 SaveCoordinator 补偿，重试不会再次增加亲密度。
4. 诊断战斗重建与战败退出显式结束旧会话请求；战败回家释放探索预钉资源。Claw 仅做已有调用与条件编译兼容，专项继续延期。
