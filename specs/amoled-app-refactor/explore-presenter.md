## 范围与验收

- Presenter 拥有主宠/跟宠插值、相机、行走/地图/Boss 动画时钟、生态/草丛表现、日照、只读模型及脏区计算。
- Session 继续独占地图、路线与玩法状态。Presenter 只借用 const 引用；不持有 App、硬件、存储、缓存，不复制地图或游戏状态，不在逐帧路径分配堆内存。
- App 保留触摸/场景仲裁、玩法完成确认、资源预载、音频、保存、缓存失效、实际重绘请求以及出门/回家淡变。
- 36 条固定路线地图/事件/RNG 指纹保持一致。覆盖四方向主宠与跟宠、相机边界、退场、暂停/回绕、静止页和局部/全帧像素一致。
- 按本批新鲜基线比较应用和 RAM 常驻段；资源包、分区、存档 schema 不变。
- 用户已授权刷机和测试。识别设备后使用匹配的固件与资源，保留 NVS/凭据；实机结果以实际连接、刷入及日志为准。

## 实现

新增 `app/ExplorePresenter.{h,cpp}` 并加入唯一权威清单 `app/sources.txt`，V1/V2、原生与 Web 共用。生产状态只读，输入通过显式参数传递。`updateMotion()` 返回固定枚举，App 随即通知 Session 完成步进/退场并消费玩法效果；新图先 reset 表现再允许下一步。

Presenter 汇总矩形脏区，`takeDamage()` 一次消费。`recordDrawn()` 只记录调用方已绘制的模型，不冒充屏幕传输成功；地图/视口变化或切出探索会使旧边界失效。App 仍拥有原有绘制/传屏确认语义。

暂停由 Session 保留唯一锚点，恢复时将暂停时长显式交给 Presenter 重排移动、退场及动画时钟。生态和草丛继续复用共享模拟规则。日照更新也由 Presenter 产生地图范围脏区。
