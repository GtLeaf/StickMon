# 吉利蛋：暖心小屋交互设计

日期：2026-11-07。状态：用户确认后实施，微雪 V1/V2 接入；谷仓／Stick 未接入。
规则来源为 [需求](requirements.md) 第 10～12 条与 [设计](design.md) “吉利蛋”一节，
本页确定流程、页面、演出及实现时补充的边界。界面延续耿鬼／变隐龙的微雪 368×448 面板。

2026-11-14：照料功能尚未完善，仅 Debug 包开放。Release 不注册吉利蛋服务，
使用普通 NPC 对话，并拒绝直接打开照料面板；存档中的照料记录保持兼容。
市集整体入口当前仍仅 Debug 开放，此限制不在本次调整范围内。

## 流程

```
靠近吉利蛋 → 点聊天气泡 → 双方转向 → 招呼框升起（约600ms后自动或点击打开）
   └→ 首页
        ├ 亲密按摩 → 选队员 → 确认 → 演出 → 结果 → 回首页
        ├ 伙伴茶会 → 选伙伴（可滚动）→ 确认 → 演出 → 结果 → 回首页
        └ 关系评估 → 选对象 → 评估页（可直接去预约按摩／茶会）
   首页右上「×」或点面板外 → 面板收起 → 恢复行走（子页点面板外＝返回）
```

招呼：“吉利蛋：欢迎来到暖心小屋！今天想照顾哪位伙伴呢？”；本期次数用完时为
“吉利蛋：本期预约满了，评估还是免费的哦。”。打开／收起动画、面板外点击不穿透、
锁屏／熄屏暂停与耿鬼一致（共用 MarketStallMotion）。

## 页面

- **首页**：标题“暖心小屋”＋右上「×」；三行 68px：亲密按摩／伙伴茶会／关系评估，
  只有图标和名称（爱心、茶杯、放大镜均为代码绘制）。底部 16px 灰字“本期可预约 n/2”。
  不可用项灰显，点击后该行下方以红字显示原因 1.8 秒（次数已满、没有可服务的伙伴）。
- **选择页**：标题＋三行 56px 可拖动列表（216～384），底部“返回”。每行 48px 头像、
  32px 名字、16px 副行和右侧状态。按摩列表只含正式队员；茶会／评估列表为正式队员在前，
  其后是不在队伍里的本地伙伴（仓库记录）。市集游客、外部访客（Origin::VISITOR）不列出。
- **确认页**：头像＋标题；两行 32px 前后变化；16px 补充行；16px“金币 a -> b / 次数 n -> n-1”；
  不可用时红字原因；底部“返回”／“按摩150”或“茶会200”，不可用时主按钮灰显。
- **评估页**：头像＋名字；亲密数值与 0～255 进度条；羁绊等级与数值；未入队伙伴显示
  邀请成功率；一条培养建议（两行 16px）。主按钮为推荐服务（“预约按摩”／“预约茶会”），
  推荐服务不可用而另一项可用时换成另一项；都不可用时只有“返回”。

## 演出

确认后先在实时状态扣款、改数值和额度并 `saveState()`；保存失败整体回滚，确认页红字
“预约未完成，请重试”，不播演出。成功后面板缩回底部 120px 对话框（镜头回到招呼位置），
框内左侧吉利蛋与对象的头像轻跳，按摩在对象上方飘三颗爱心，茶会在两者之间画茶杯与爱心；
右侧先显示“按摩中…／茶会中…”，约 1.2 秒后显示结果：

- 按摩：32px“亲密+10”（满值附近为实际值），16px“XX放松下来了”，达到亲密进化条件时
  加一行“下次升级时可能进化”。
- 茶会：32px“羁绊+5”，16px 按结果等级的一句对白，跨级时加一行“初识 -> 熟悉”。

演出中点击直接跳到结果；结果页点击后对话框展开回首页。奖励已在演出前保存，跳过／
锁屏不会重复发放。

## 规则（MarketCareService）

| 项 | 值 |
| --- | --- |
| 亲密按摩 | 150 金币；正式队员亲密 +10（封顶 255）、心情 +10（封顶 100） |
| 伙伴茶会 | 200 金币；羁绊 +5（封顶 100） |
| 关系评估 | 免费，不占次数 |
| 次数 | 每期开集全摊 2 次；每只精灵每期 1 次，按摩与茶会共用 |

开集间隔3、4个游戏日交替、每次开放1天，详见[周期集市](periodic-market.md)。闭市保留上期额度，下一次开集才重置；闭市不接受新预约，并释放误触发的摊主对话。

- 个体按 ivPacked＋metAt 记录（同耿鬼特训），换队、进化、重进、重启不重置。
- 不可服务（不扣款、不占次数）：亲密已满（按摩）／羁绊已满（茶会）、倒下、访客、
  本期已服务、次数已满、金币不足、期号已过（确认页记下的期号与当前不同）。
- **首次邀请保底**：未入队伙伴羁绊仍为初始 10 且从未一起探索时，第一次邀请必定成功；
  茶会会让它失去该保底，因此禁用并提示“先邀请它吧”。
- 已入队对象修改实时值并 `ContactRoster::syncTeamContacts` 同步伙伴记录；未入队对象
  修改仓库记录。不改队伍编成、邀请锁定（当天已拒绝仍需明天）、HP、饱腹或照料经验。
- 按摩达到亲密进化条件时只提示，沿用原升级进化检查，不当场进化。
- 培养建议优先级：倒下→先休息；首次邀请保底→去邀请；羁绊<25→喝茶；正式队员亲密<220
  →按摩；羁绊<75→一起探索；否则→已是挚友。

## 存档

当前SAVE_VERSION9、SaveCodec schema8保留 `MarketCareState`（期号 u32、已用次数 u8、
两条 ivPacked/metAt 记录，编码21字节），兼容早期schema与rawv8。早于照料字段的旧档读入为空；损坏记录（次数>2 或无期号却
有记录）只清空本期，不补偿。

## 验证

`python3 tools/test_market_care.py [--output DIR]`：规则 ASan/UBSan（各拒绝原因、封顶、
首次邀请保底、共享额度、个体绑定、跨期、队伍同步、存档往返与坏档）及真实 AmoledApp
旅程（气泡入口、招呼、首页次数、按摩确认／保存失败回滚／成功演出跳过、茶会滚动与跨级、
评估跳转预约、额度用尽、「×」关闭恢复行走）。
