# StickMon on OSTB 3ST

This target runs the original two-button game directly on the verified 296x240 NV3023 display without LVGL. It is independent of the Waveshare firmware. Development branch: `codex/ostb-3st-adaptation`.

## Build and flash

Load ESP-IDF 5.5.x, then run `idf.py build` in this directory. Run `./flash.sh /dev/cu.usbmodem2101` for matching bootloader, partition table, app and resources. Upload speed is 115200. Preserve the game's NVS on normal upgrades.

First provision only: the new `game_nvs` partition at 0x700000, size 0x10000, must be blank before its first use. It is separate from the original NVS. Do not repeat that erase on updates. The target fails initialization instead of erasing an invalid store automatically. The current development device has already been provisioned.

The full original firmware backup is maintained privately outside this repository. Restoring the factory 16MiB image also replaces the game's storage, so back up the game's partition before restoring if progress is needed.

## Hardware status

- ESP32-S3; 16MiB flash, 8MiB octal PSRAM confirmed, memory test passed.
- Display: 296x240 landscape; NV3023; offset (24,0), MADCTL 0xe8, RGB565, 40MHz SPI3. MOSI10 CLK9 CS14 DC8 RESET18 BL13.
- Startup keeps GPIO13/backlight off, defers panel display-on, and waits for the first full-frame DMA transfer to finish before lighting the screen. Loading saved brightness cannot expose uninitialized panel RAM. The user confirmed that a cold power-on now shows the normal game without startup garbage.
- Room and sprites use the same 1x pixel size as StickS3. The full 240x161 room is centered at (28,39), with black margins and no camera movement. Main/visitor sprites, food, eggs and shadows share that origin and preserve their original pixel sizes. World layers are clipped to the room; the clock and one/two monster status panels use the upper margin, with tutorial hints below. Menus and other scenes keep the full native canvas. Host checks and three target builds passed; this centered presentation awaits device feedback and supersedes the previously accepted 2x camera version.
- A=GPIO40, B=GPIO39, active low, physically confirmed.
- Screen touch: the device ACKs at 0x15 on shared SDA12/SCL11 and reports chip ID 0xb8. The CST816-compatible register reader polls at 20ms. First startup asks for four corner taps and one center check; hold each cross briefly, then release. Setup uses the median of the latest five samples and shows retry guidance. A missed center can be retried twice before restarting. B skips touch for this boot; A+B held at boot requests setup again. Calibration has separate `ostb_touch/cal_v1` storage and does not change the game snapshot. Physical calibration passed with 2.60px center error and saved=1. The user confirmed main-monster petting, bowl feedback, menu rows and bottom navigation; egg/shop/settings touch have host coverage.
- The main menu shares the AMOLED icon-grid renderer. Columns follow the available width: OSTB displays three 88x72 cards per row and all eight release entries on one screen; AMOLED keeps its two-column layout. Pressing highlights a card and releasing activates it. Bag/shop use adaptive item grids with vertical dragging, a Back control, and separate detail views with Use/Buy/Sell actions. Using an item retains the original confirmation popup. Consuming/selling the final copy returns to the grid. Room, food, settings and the computer entry use a circular Back header and direct cards/rows without the Select/Confirm strip. Food lists all seven foods with stock and selection, with vertical scrolling. Settings has brightness/volume sliders, scrolling, help page controls and an isolated reset confirmation defaulting to Cancel. Computer contact/communication child pages and other unchanged submenus retain their existing Back/Select/Confirm strip. Drags and interrupted contacts cannot click. A/B still select/open/return, and static grids/details park until input or a timed change. Bath dragging and exploration/battle touch controls remain outside this delivery.
- Middle power key: GPIO1, active high, with both internal pulls disabled, recovered from this device's original 2.2.2 firmware. GPIO0 in the public 3ST reference is a different mapping. Short press locks/unlocks. Long press cuts hardware power; starting from that state also requires a long press, as confirmed by the user. Each debounced press saves before hardware cutoff. Gameplay pauses while the key is held to keep the displayed position aligned with the snapshot; the user confirmed both the pause and correct position after power-on. Save/startup logs match at world position (132.00,123.00). Software deep sleep on long release is a fallback and remains unverified. See `specs/ostb-3st-port/hardware-evidence.md`.
- The team list uses two 280x76 member cards with normal 8px side margins with bounded front sprites, name/level/HP and status indicators. Release a card to open its action popup; tap outside to dismiss without click-through. The leader offers Status/Moves; eligible permanent partners also offer First/Leave, with Leave unavailable during exploration. Visitors retain Status/Moves only. A/B still cycle/open/back. Egg viewing and exploration return remain available. Status and moves preserve the original body composition with only the safe circular Back header added; no bottom Select/Confirm or Previous/Next strip is present. Status keeps its original five pages with a bottom-centered indicator drawn above content, uses horizontal swipes/header-title taps for paging and vertical dragging for overflow. Moves keeps the 90px list, 24px rows, original details/bar, description marquee and compact default-No forget popup. Tap a row to inspect and tap the selected row to run the existing action. Only top navigation keeps 28px horizontal corner clearance at (28,4)-(268,44). The independent body viewport is (0,48,296,176); cards, details, modals and hit tests do not inherit that inset. Other page groups remain deferred, and R56+6px is still a design estimate per `specs/ostb-3st-port/safe-area.md`.
- ES8311 speaker at I2C 0x18 responds and opens successfully. SDA12 SCL11, MCLK5 BCLK15 WS16 DOUT6 AMP4. Sound still needs listening confirmation. Microphone disabled.
- No verified IMU: hold A to scrub during soap/brush phases; B returns to the bath tools.
- Home shows the shared AMOLED battery icon immediately after the clock. ADC2 CH6/GPIO17 uses the original factory 12dB/12-bit setup and recovered raw-to-percent curve, with eight-sample averaging, 80/20 smoothing and ten-second caching. Read failure/zero/saturation shows the unknown dash. This is a voltage-based estimate; charging detection and full-cycle calibration remain pending.
- NVS snapshots and ESP-NOW protocol use the shared services and formats. Cross-device radio testing is pending.
